## 二、官方做法：官方 Qwen2 模型结构树

### 2.1 顶层结构：`Qwen2ForCausalLM` 装了什么

最外层的类只有**两个直接成员**：一个负责"理解"的主干，一个负责"输出词"的头。

```1147:1149:example1/huggingface/baseline_models/qwen2/modeling_qwen2.py
        self.model = Qwen2Model(config)

        self.lm_head = nn.Linear(config.hidden_size, config.vocab_size, bias=False)
```

```
Qwen2ForCausalLM  ← 顶层：负责「语言生成」这个任务
├── self.model   = Qwen2Model   ← 主干：把 token 编码成语义向量
└── self.lm_head = nn.Linear     ← 输出头：语义向量 → 词表分数（独立挂在顶层，和 model 平级）
```

- **`Qwen2Model`**：模型的"身体"，把输入的词编码成一串富含语义的向量。
- **`lm_head`**：模型的"嘴"，把最后的语义向量翻译成"下一个词是词表里每个词的分数（logits）"。它**不在任何一层里**，直接挂在顶层——所以适配时要给它单独一个转换方法（见 3.2.4）。

#### 2.1.1 lm_head 的输入输出形状

```
输入 [B, seq, hidden]  ──lm_head: Linear(hidden → vocab)──▶  输出 [B, seq, vocab]
```

只把**最后一维**从 `hidden_size`（如 2048）投影成 `vocab_size`（如 151936），`B`、`seq` 不变（逐 token 独立、只作用在最后一维）。含义：

- **输出 `[b, i, :]`** = 第 `b` 句、第 `i` 个位置对"**下一个 token**"的全词表分数（logits）；softmax 后即"下一个词"的概率分布（见 [附录J](./02-附录J-采样策略(logits到下一个token).md)）。这个"下一个"是关键——第 `i` 位输出预测第 `i+1` 个词（PPL 里 `shift_logits` / `shift_labels` 错开一位对齐正因如此）。

> ⚠️ **易混点：入口的"词向量" ≠ 出口喂给 lm_head 的向量**。两者形状都是 `[B, seq, hidden]`，但含义完全不同：

| 位置 | 形状 | 含义 | 叫什么 |
|------|------|------|--------|
| `embed_tokens` 输出（入口）| `[B, seq, hidden]` | 刚查表得到、**只代表词本身、无上下文** | **词向量 / 词嵌入** |
| `lm_head` 输入（出口）| `[B, seq, hidden]` | 经 N 层 Attention+MLP+final norm 加工、**已融合整句上下文** | **隐藏状态 / 语义向量** |

> 所以 lm_head 的输入应叫"**隐藏状态**"而非"词向量"——正因为它已吸收上下文，才能据此预测合理的下一个词。（decode 模式下可只返回最后 `ARN` 个位置的 logits 省算力，见 `num_logits_to_return`。）

### 2.2 主干 `Qwen2Model` 里面又有什么

```925:930:example1/huggingface/baseline_models/qwen2/modeling_qwen2.py
        self.embed_tokens = nn.Embedding(config.vocab_size, config.hidden_size, self.padding_idx)
        self.layers = nn.ModuleList(
            [Qwen2DecoderLayer(config, layer_idx) for layer_idx in range(config.num_hidden_layers)]
        )
        self._attn_implementation = config._attn_implementation
        self.norm = Qwen2RMSNorm(config.hidden_size, eps=config.rms_norm_eps)
```

三部分：**入口 embedding → N 层 Decoder → 收尾归一化**。

```
Qwen2Model
├── embed_tokens (Embedding)     词编号 → 向量（入口）    [B,seq] → [B,seq,hidden]
├── layers (N × Qwen2DecoderLayer)   N 层 Transformer 反复加工
└── norm (RMSNorm)               最后归一化
```

每一层 `Qwen2DecoderLayer` 是标准的 "Attention + MLP" 三明治（各带一个 RMSNorm 和残差）：

```722:726:example1/huggingface/baseline_models/qwen2/modeling_qwen2.py
        self.self_attn = QWEN2_ATTENTION_CLASSES[config._attn_implementation](config, layer_idx)

        self.mlp = Qwen2MLP(config)
        self.input_layernorm = Qwen2RMSNorm(config.hidden_size, eps=config.rms_norm_eps)
        self.post_attention_layernorm = Qwen2RMSNorm(config.hidden_size, eps=config.rms_norm_eps)
```

```
Qwen2DecoderLayer（每层，Pre-Norm 结构）
├── input_layernorm (RMSNorm)
├── self_attn  ← Attention：q/k/v/o_proj，跨 token 交流   → 附录A
│              （+ 残差）
├── post_attention_layernorm (RMSNorm)
└── mlp        ← MLP：gate/up/down_proj，逐 token 深加工   → 附录H
               （+ 残差）
```

> 每层是 **Pre-Norm** 结构：`x → norm → 子层 → +残差`；norm 稳数值、残差给梯度留高速公路。RMSNorm、Pre-Norm、残差、以及所有层跑完后的 final norm，详见 [附录I](./02-附录I-层结构-Norm与残差.md)。

#### 2.2.1 完整结构树 + 数据流

```
input_ids [B,seq]
   │
   ▼  Qwen2ForCausalLM
      └── model (Qwen2Model)
          ├── embed_tokens ──────────────▶ [B,seq,hidden]   词→向量
          ├── layers[0..N-1]  每层：
          │      ├─ input_layernorm
          │      ├─ self_attn  (Attention) ─┐跨token
          │      ├─ + 残差                   │
          │      ├─ post_attention_layernorm │
          │      ├─ mlp        (MLP/SwiGLU) ─┘逐token
          │      └─ + 残差
          └── norm ───────────────────────▶ [B,seq,hidden]  最终语义向量
      └── lm_head ───────────────────────▶ [B,seq,vocab]   向量→词表分数(logits)
   │
   ▼  softmax → 采样 → 下一个 token
```

> `embed_tokens`（词→向量）和 `lm_head`（向量→词）是一头一尾的逆操作，常**共享权重**（`_tied_weights_keys = ["lm_head.weight"]`），省下一大块参数。

## 三、本项目改造后的做法：替换全景与逐项说明

### 3.1 适配替换全景：每个零件被换成了什么

适配集中在 `llm_quant.py` 第 50-61 行，把上面结构树里的几个零件运行时替换成端侧量化版：

```51:61:example1/llm_quant.py
modeling_qwen2.QWEN2_ATTENTION_CLASSES['eager'] = QcAttention
assert update_attr(modeling_qwen2.Qwen2Model, '_update_causal_mask', bypass_update_causal_mask) or \
       update_attr(modeling_qwen2.Qwen2Model, '_prepare_decoder_attention_mask', bypass_update_causal_mask), \
    f"neither _prepare_decoder_attention_mask(..) nor _update_causal_mask(..) found, Unknown Qwen2Model definition in {modeling_qwen2.__file__}"
setattr(modeling_qwen2.Qwen2MLP, 'prepare_conv', MLP_prepare_conv)
setattr(modeling_qwen2.Qwen2MLP, 'forward_conv', MLP_forward_conv)
setattr(modeling_qwen2.Qwen2ForCausalLM, 'prepare_conv', ForCausalLM_prepare_conv)
assert update_attr(cache_utils.DynamicCache, 'update',
                   DynamicCache_update), f"Unknown DynamicCache definition: {cache_utils.DynamicCache}"
assert update_attr(cache_utils.DynamicCache, 'get_seq_length',
                   DynamicCache_get_seq_length), f"Unknown DynamicCache definition: {cache_utils.DynamicCache}"
```

把它们对应到结构树里的位置：

| 结构里的零件 | 位置 | 被换成 | 为什么 | 详见 |
|-------------|------|--------|--------|------|
| **Attention 类** | 每层 `self_attn` | `QcAttention`（整类替换）| Linear→Conv、量化感知加法、外部 RoPE、逐层掩码缩放 | [附录A](./02-附录A-Attention注意力机制.md) |
| **因果掩码生成** | `Qwen2Model._update_causal_mask` | `bypass_update_causal_mask`（透传）| 掩码改由外部输入，利于定长导出 | [附录E](./02-附录E-端侧定长与计算图导出.md) |
| **MLP** | 每层 `mlp` | 挂 `prepare_conv`/`forward_conv` | 三个 Linear → 三个 1×1 Conv | [附录B](./02-附录B-Linear与Conv算子转换.md)、[附录H](./02-附录H-MLP前馈网络.md) |
| **lm_head** | 顶层 `lm_head` | 挂 `ForCausalLM.prepare_conv` | 输出头 Linear → 1×1 Conv | [附录B](./02-附录B-Linear与Conv算子转换.md) |
| **KV 缓存** | `DynamicCache.update` / `get_seq_length` | 重写 | 定长/转置缓存、只存新 KV | [附录K](./02-附录K-KV%20Cache(键值缓存).md) |

一张图看"改在哪"：

```
Qwen2ForCausalLM
├── model
│   ├── embed_tokens                （不改）
│   ├── layers[i]
│   │   ├── self_attn  ── 换整类 → QcAttention          ✅改
│   │   └── mlp        ── 挂方法转 1×1 Conv               ✅改
│   ├── norm                        （不改）
│   └── _update_causal_mask ── 换成透传 bypass            ✅改
└── lm_head            ── 挂方法转 1×1 Conv               ✅改

（另：全局 DynamicCache 的 update/get_seq_length 被重写   ✅改）
```

### 3.2 替换项逐个简述

#### 3.2.1 Attention → `QcAttention`（整类替换）
不是"补方法"，而是把 `QWEN2_ATTENTION_CLASSES['eager']` 直接指向自定义类 `QcAttention`，于是每层 `self_attn` 实例化时用的就是量化版（`forward` 被换成 `forward_conv`，原版备份为 `forward_no_conv`）。主要改动：q/k/v/o_proj 转 1×1 Conv、支持外部传入 cos/sin 的 RoPE、K 转置存对接定长 KV、`1/√d` 缩放提前、用 `aimet_torch` 的 `Add` 替代 `+` 且逐层掩码缩放（layer0×2/layer27×10）、去掉推理无用的 dropout。**算法本质不变**。→ **官方 vs QcAttention 逐段对照见 [附录A 第四节](./02-附录A-Attention注意力机制.md#四本项目改造后的做法官方-vs-qcattention-逐段对照)**

#### 3.2.2 因果掩码 → `bypass_update_causal_mask`（透传）
官方会在 forward 里**动态构造**下三角因果掩码；端侧改成**掩码由外部输入直接喂进来**，所以这里把生成函数替换成"原样返回"。⚠️ 改的是掩码的**来源**（动态生成→外部输入），不是"有没有掩码"。→ [附录E](./02-附录E-端侧定长与计算图导出.md)

#### 3.2.3 MLP → `prepare_conv` + `forward_conv`（补方法）
给 `Qwen2MLP` 挂两个方法：`prepare_conv` 一次性把 `gate/up/down_proj` 三个 Linear 换成 1×1 Conv 并搬权重；`forward_conv` 每次推理做 Conv 版 SwiGLU（reshape/transpose 摆形状 + 三次卷积）。→ [附录B](./02-附录B-Linear与Conv算子转换.md)、[附录H](./02-附录H-MLP前馈网络.md)

#### 3.2.4 lm_head → `ForCausalLM.prepare_conv`（补方法）
因为 `lm_head` 独立挂在顶层、不在任何 MLP/Attention 里，`MLP_prepare_conv` 够不着，所以给**顶层类**单独挂一个 `prepare_conv`，把这个 `hidden→vocab` 的巨型 Linear 也转成 1×1 Conv。→ [附录B](./02-附录B-Linear与Conv算子转换.md)

> 第 3、4 的补方法，靠加载后的统一循环触发（`for module in model.named_modules(): if hasattr(module,'prepare_conv'): module.prepare_conv()`）——`named_modules()` 会遍历到每个 MLP 和顶层模型，谁有 `prepare_conv` 就调谁的。

#### 3.2.5 KV 缓存 → 重写 `DynamicCache.update` / `get_seq_length`
端侧 KVCache 模式下只保留新算的 K/V（历史由外部管理）、并可转置存储，所以缓存的更新与长度查询逻辑要改写。→ [附录K](./02-附录K-KV%20Cache(键值缓存).md)

### 3.3 两种替换手法（速记，详见 Monkey-Patch 篇）

| 手法 | 写法 | 用在哪 | 特点 |
|------|------|--------|------|
| **换整类** | `QWEN2_ATTENTION_CLASSES['eager'] = QcAttention` | Attention | 直接换实现类 |
| **补方法** | `setattr(Qwen2MLP, 'prepare_conv', ...)` | MLP、lm_head | 给原类加新方法，原类不变 |
| **`update_attr`（带备份+校验）** | `update_attr(DynamicCache, 'update', ...)` | 掩码、KV 缓存 | 原方法不存在则报错、并备份原版可还原 |

## 四、记忆锚点

- 模型三层套娃：**`Qwen2ForCausalLM` = `Qwen2Model` + `lm_head`**；`Qwen2Model` = `embed_tokens` + N×`DecoderLayer` + `norm`；每层 = `Attention` + `MLP`（各带 RMSNorm+残差）。
- 数据流首尾：**`embed_tokens` 词→向量（入口）→ N 层加工 → `norm` → `lm_head` 向量→词表分数（出口）**；首尾常共享权重。
- 适配改 5 处：**Attention 换整类、掩码改透传、MLP 转 Conv、lm_head 转 Conv、KV 缓存重写**；官方源码一行没动。
- `lm_head` 要单独转，是因为它**独立挂在顶层**、不在任何层里。
- 三种手法：**换类 / 补方法(setattr) / update_attr(带备份校验)**。
- 一句话：**先看懂"结构树"，再看每处适配钉在树的哪个位置，就不会在 1552 行官方文件里迷路。**
