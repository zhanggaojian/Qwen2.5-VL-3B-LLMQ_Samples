## 一、介绍：Attention 的两个定语——"自" 与 "自回归"

附录A 讲了 Attention 怎么算，本篇补它的两个前缀概念：

- **自注意力**：Q、K、V 都来自**同一句话自己**，让句子内部的词互相看（数据从哪来）。
- **自回归**：生成时**一次只吐一个词**，把它接回输入当下一步条件，循环往复（词怎么一个个蹦）。

下面 ② 把这两个概念各自讲透，并串成 Decoder-only 模型的运行骨架。

## 二、原理

### 2.1 自注意力（Self-Attention）

#### "自"字到底自在哪？

Attention 的本质是"Q 去找 K、按相关性取 V"（见附录A）。区别只在于：**Q 和 K/V 是不是来自同一段序列**。

| 类型 | Q 来自 | K/V 来自 | 直觉 |
|------|--------|----------|------|
| **自注意力** Self-Attention | 序列**自己** | 序列**自己** | 句子内部的词互相看 |
| 交叉注意力 Cross-Attention | 序列 A（如解码端） | 序列 B（如编码端/图像） | 一段去看另一段 |

所以"自注意力"就是：**Q = K = V 的来源都是同一个 `hidden_states`**。回看附录A 第三节官方源码：

```python
query_states = self.q_proj(hidden_states)   # Q ← hidden_states
key_states   = self.k_proj(hidden_states)   # K ← 同一个 hidden_states
value_states = self.v_proj(hidden_states)   # V ← 同一个 hidden_states
```

三个投影的输入是**同一个** `hidden_states` → 这就是"自"。Qwen2 的每一层 Attention 都是自注意力。

#### 为什么需要"自己看自己"

一个词的含义取决于上下文（同一句里的其他词）。自注意力让每个 token 扫描**同句中所有 token**，按相关性把信息汇进自己的表示里：

```
"猫累了，因为它睡了一天"
          └它┘ 自注意力 → 高度关注同句里的"猫" → "它"的向量融入"猫"的信息
```

> 对比卷积/RNN：自注意力是**任意两个位置直接相连**（一步到位），不受距离衰减，这正是 Transformer 能抓长距离依赖的根本。

#### 多模态(VL)里的小提醒

本项目是 Qwen2.5-**VL**（含图像）。在 LLM 主干里，图像会先被编码成一批 **image token**，**拼进同一条 seq** 和文本 token 排在一起，然后照样走自注意力。所以从 LLM 角度看，图文是"同一句话"，仍是自注意力，无需单独的交叉注意力模块。

### 2.2 自回归（Autoregressive）

#### 一句话定义

**自回归 = 用"自己已经生成的内容"作为条件，去预测下一个词，逐个生成。** 名字里：
- **自(auto)**：回归到的输入就是模型**自己之前的输出**。
- **回归(regressive)**：用历史预测下一个值。

#### 生成过程（逐步循环）

```
输入: "今天天气"
 step1: 模型看 [今天 天气]        → 预测下一个 token: "真"
 step2: 把"真"接回 → [今天 天气 真] → 预测: "好"
 step3: [今天 天气 真 好]          → 预测: "！"
 ...直到生成 <eos>(结束符) 停止
```

每一步都：**取目前全部序列 → 算一次前向 → 取最后一个位置的输出 → 采样出一个新 token → 拼回序列**。这就是"一个词一个词蹦"的由来。

> 训练时不用真的一步步蹦：用 **teacher forcing** 一次喂入整句、并行预测每个位置的下一个词；推理时才是逐步自回归。

#### 自回归 ↔ 因果掩码（必须配对）

要保证"预测第 i 个词时只能看前面、不能偷看后面"，否则训练时会作弊。做法是在 softmax 之前给"未来位置"的分数加上 $-\infty$，即**因果掩码（Causal Mask）**：

```
        能看的位置(✓) / 被屏蔽(✗)
词0:  ✓ ✗ ✗ ✗
词1:  ✓ ✓ ✗ ✗      ← 下三角：每个词只能看自己和左边
词2:  ✓ ✓ ✓ ✗
词3:  ✓ ✓ ✓ ✓
```

> 因果掩码细节见附录A 第三节第 7 步、笔记 02 · 4.2.2（bypass 因果掩码）。**自回归是"目标"，因果掩码是"实现手段"**。

#### 自回归 ↔ KV Cache（推理提速）

逐步生成时，新词要和**前面所有词**算 Attention。每步重算历史的 K/V 很浪费，于是把历史 K/V **缓存**起来，新词只算自己的，拼上缓存即可——这就是 **KV Cache**。

- 没有自回归这种"逐步、且历史不变"的特性，就没有 KV Cache 的优化空间。
- 代码里 `past_key_value.update(...)` 维护缓存；本项目对它做了端侧定长改写（见笔记 02 第 4 节、附录A 2.6）。

### 2.3 两者怎么串起来（全景）

```
自注意力(算法核心) ──组成──▶ 每一层 Transformer
        │
        ▼
   配 因果掩码 (只看左边)
        │
        ▼
   自回归循环 (吐一个→接回→再吐)
        │
        ▼
   用 KV Cache 提速 (历史不重算)
```

一句话：**用"自注意力"理解上下文，配"因果掩码"防偷看，按"自回归"逐词生成，靠"KV Cache"省算力。** 这四件套就是 GPT 类（Decoder-only，Qwen2 也是）模型的运行骨架。

---

## 三、记忆锚点

- **自注意力**：Q/K/V 同源（都来自 `hidden_states`）→ 句内互相看。
- **交叉注意力**：Q 与 K/V 不同源（本项目 LLM 主干用不到，图文同 seq）。
- **自回归**：拿自己的输出当下一步输入，逐词生成，遇 `<eos>` 停。
- **配对关系**：自回归 ↔ 因果掩码（防偷看）↔ KV Cache（提速）。
- Qwen2 是 Decoder-only：**全程自注意力 + 自回归**。
