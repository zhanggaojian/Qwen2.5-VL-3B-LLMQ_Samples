# 05 · 通用前向处理流程：LLMForwardPassManager

> **流程位置**：承接 [04-PPL 困惑度评估](./04-PPL困惑度评估.md)。PPL、prepare 后验证、量化校准和量化后评估虽然目的不同，但最终都会走同一套“准备输入 → 执行模型 → 整理输出”的前向路径。
>
> **一句话本质**：`LLMForwardPassManager`（下文简称 FPM）把真实世界的变长输入、变长历史 KV、位置和掩码，整理成端侧固定计算图需要的固定形状；模型算完后，再去掉 dummy padding，并把有效 logits 与 KV Cache 还原出来。
>
> **本篇边界**：这里讲的是一次通用前向如何运行，不是下一阶段 AIMET 的“模型 prepare”。`prepare_inputs()` 是运行时输入整理；AIMET prepare 是模型图转换，两者只是名字相似。

---

## 一、介绍：为什么模型外面还需要一层 FPM

### 1.1 官方模型可以接收变长输入

在普通 PyTorch / Hugging Face 推理中，可以直接写：

```python
outputs = model(
    input_ids=input_ids,
    attention_mask=attention_mask,
    past_key_values=past_key_values,
)
```

序列长度可以随请求变化，模型内部还可以动态完成：

- `input_ids → inputs_embeds`；
- 根据当前位置生成 RoPE；
- 根据输入长度生成 causal mask；
- 动态追加 KV Cache；
- 返回当前长度对应的 logits。

GPU/PyTorch 很擅长这种动态执行，但端侧 NPU/HTP 更偏好提前编译好的静态计算图：输入名、输入数量和各维 shape 最好每次完全一致。

### 1.2 本项目把“动态工作”挪到模型外面

本项目的处理边界是：

```text
变长世界（模型外）                         定长世界（模型内）

真实输入 L                         固定 current = ARN
真实历史 KV                       固定 past = context_length - ARN
真实有效位置       ── FPM ──▶      固定 attention / RoPE shape
                                                  │
                                                  ▼
                                         Qwen2 固定计算图
                                                  │
有效 logits、有效 KV  ◀── FPM ──     定长 logits、新 KV
```

所以 FPM 不是新的神经网络层，也不会学习参数。它是模型外面的运行时适配器，负责形状、mask、位置与缓存管理。

### 1.3 当前项目中的三个核心长度

配置为：

```yaml
context_length: 2048
arn: 1073
```

FPM 中对应：

```python
self.max_tokens = tokenizer.model_max_length  # 2048
self.num_tokens = num_tokens                  # 1073，即 ARN
desired_kv_length = max_tokens - num_tokens   # 975
```

不要把三者混成一个长度：

| 对象 | 当前固定长度 | 含义 |
|---|---:|---|
| 当前输入 | `ARN = 1073` | 这一次送入模型计算的 token/embedding 槽位 |
| Past KV | `2048 - 1073 = 975` | 模型输入端为历史预留的槽位 |
| Attention 总可见范围 | `2048` | 历史 975 + 当前 1073 |

## 二、原理：一次前向就是三段式

FPM 的核心代码位于 `example1/llm_utils/forward_pass_wrapper.py`：

```python
def __call__(self, *args, **kwargs):
    prepared_inputs, info = self.prepare_inputs(*args, **kwargs)
    outputs = self.model(**prepared_inputs)
    prepared_outputs = self.prepare_outputs(outputs, prepared_inputs, info)
    return prepared_outputs
```

它可以压缩成三个阶段：

```text
① prepare_inputs
   变长数据 → 定长模型输入

② self.model
   执行真正的 Qwen2 Transformer

③ prepare_outputs
   定长模型输出 → 有效 logits + 有效 KV Cache
```

### 2.1 `info` 为什么必须保留

`prepare_inputs()` 不只返回 `prepared_inputs`，还返回 `kvcache_info_bundle`。其中至少记录：

```python
info["input_length"] = 原始当前输入长度
info["kv_padding_length"] = Past KV 前面补了多少 dummy
```

因为输入补齐后，模型只看到固定 shape，已经无法仅凭输出判断哪些位置原本是真实数据。FPM 必须把补齐前的长度单独记下来，供 `prepare_outputs()` 恢复有效部分。

这也是理解本篇最重要的一组对应关系：

```text
attention mask       → 模型计算时屏蔽无效位置
input_length         → 模型算完后裁掉无效 logits / 新 KV
kv_padding_length    → 模型算完后裁掉历史 KV 中的 dummy
```

它们职责相关，但不是同一件事。

## 三、官方 Qwen2 的前向执行方式

官方调用链大致为：

```text
Qwen2ForCausalLM.forward
        │
        ├─ Qwen2Model.forward
        │    ├─ input_ids → embed_tokens（如果没有直接传 embedding）
        │    ├─ 动态生成 causal mask / position
        │    ├─ Decoder Layer × N
        │    └─ final RMSNorm
        │
        └─ lm_head → logits
```

每个 `Qwen2DecoderLayer` 是 Pre-Norm 结构：

```text
hidden
  ├──────── residual_1
  ▼
input RMSNorm
  ▼
Self Attention（这里计算当前 K/V，并读取历史 KV）
  ▼
residual_1 + attention_output
  ├──────── residual_2
  ▼
post-attention RMSNorm
  ▼
MLP
  ▼
residual_2 + mlp_output
```

所有 Decoder Layer 完成后，还要执行：

```text
final RMSNorm → lm_head → logits
```

因此“模型前向”不只等于 Attention；Attention、MLP、两次层内 RMSNorm、两次残差、最终 RMSNorm 和 lm_head 都属于模型执行阶段。

## 四、本项目的通用前向处理流程

### 4.1 调用入口：长序列先分块

PPL 评估不是直接调用 FPM，而是先进入：

```python
slice_inputs_and_run_successive_kvcache_inference(...)
```

它负责：

1. 把长序列切成每块不超过 `ARN`；
2. 每块调用一次 `fpm(...)`；
3. 把上一块输出的 KV Cache 传给下一块；
4. 按原顺序拼接各块 logits。

以 `context_length=2048、ARN=1073` 为例，代码不是简单切成 `1073 + 975`，而是让第一块成为余数：

```text
2048 个 token
   ├─ 第 1 块：975   → 左补 98 个 dummy 后送入模型
   └─ 第 2 块：1073  → 携带第 1 块产生的 975 长 KV
```

这样第二块刚好满足：

```text
Past KV 975 + Current 1073 = Context 2048
```

每一块内部仍然是并行 teacher forcing 前向；这属于连续分块前向，不是逐 token 的 decode 循环。

### 4.2 第一步：校验输入类型

FPM 要求以下三者恰好提供一个：

```python
input_text
input_ids
input_embeddings
```

当前 Qwen2.5-VL 路径使用：

```python
input_embeddings
```

因为图像已经在 dataloader 中经过视觉编码器，并替换到了文本序列中 `<image_pad>` 对应的 embedding 位置。到了 FPM 以后，不会再次执行视觉编码器。

纯文本路径则使用：

```python
input_ids
```

### 4.3 第二步：确定真实长度

在补齐之前先记录：

```python
batch_size = input.shape[0]
input_length = input.shape[1]
kv_length = past_key_values 的真实长度（若没有则为 0）
```

并保存：

```python
info["input_length"] = input_length
```

这里的 `input_length` 是原始有效长度，不是补齐后的 1073。后续截取 logits 与新 KV 都依赖它。

### 4.4 第三步：当前输入左补到 `ARN`

若 `input_length < num_tokens`，代码在当前输入左边补 0：

```python
input = torch.cat((input_extensions, input), dim=1)
```

例如：

```text
补齐前：[1000 个真实 embedding]
补齐后：[73 个零 embedding | 1000 个真实 embedding]
                         总长 = 1073
```

对于 embedding，补齐后的形状为：

```text
[B, 1073, hidden_size]
```

对于 token ID，形状为：

```text
[B, 1073]
```

之所以采用左 padding，是因为输出阶段可以统一保留最后 `input_length` 个位置。

### 4.5 第四步：Past KV 补到 975

模型输入端要求 Past KV 固定为：

```python
desired_kv_length = max_tokens - num_tokens
                  = 2048 - 1073
                  = 975
```

真实历史不足时：

```python
kv_padding_length = desired_kv_length - kv_length
```

并在历史前面创建全 0 dummy KV：

```text
真实历史长度 300
        ↓
[675 个 dummy KV | 300 个真实 KV]
             总长 = 975
```

FPM 同时保存：

```python
info["kv_padding_length"] = 675
```

当前配置还启用了 `transposed_key_cache=true`，所以每层缓存形状大致为：

```text
K：[B, num_kv_heads, head_dim, past_len]
V：[B, num_kv_heads, past_len, head_dim]
```

K 和 V 的序列轴不同，这是为端侧矩阵乘布局做的适配，不代表两者保存了不同数量的 token。

### 4.6 第五步：构造位置与 RoPE

未启用 mRoPE 时，FPM 先根据 2D attention mask 生成逻辑位置：

```python
position_ids = torch.cumsum(attention_mask, dim=1) - 1
position_ids = position_ids.clip(0, max_tokens - 1)
position_ids = position_ids[..., -num_tokens:]
```

当前配置：

```yaml
use_position_embedding_input: true
```

因此还会在模型外把 `position_ids` 转成 RoPE 的 cos/sin：

```python
position_ids = self.get_position_embeddings_from_position_ids(position_ids)
```

最终 QcAttention 收到的 `position_ids` 实际是：

```python
(cos, sin)
```

形状大致为：

```text
[1, 1, 1073, head_dim/2]
```

RoPE 只作用于当前块的 Q、K。历史 K 在它第一次作为“当前 token”时已经旋转过，进入 KV Cache 后不会重复旋转。

启用 `use_mrope=true` 时，位置来源会改为 Qwen2-VL 的时间/高度/宽度三维位置，但“在模型外生成并固定形状”这一职责不变。

### 4.7 第六步：构造 combined attention mask

补齐后的普通 mask 总长度为：

```text
Past 975 + Current 1073 = 2048
```

当前配置启用：

```yaml
use_combined_mask_input: true
```

因此 FPM 会把 padding mask 与 causal mask 合并，生成大致形状：

```text
[B, 1, 1073, 2048]
```

它同时表达两件事：

- 不能关注左侧 dummy KV / dummy input；
- 当前位置不能看到未来 token。

项目已把 `Qwen2Model._update_causal_mask()` monkey patch 成直接返回外部 mask，所以模型内部不再根据动态长度重新创建 causal mask。

### 4.8 第七步：组成 `prepared_inputs`

当前 embedding、非扁平 KV 模式下，最终字典近似为：

```python
prepared_inputs = {
    "inputs_embeds": fixed_input_embeddings,
    "attention_mask": combined_attention_mask,
    "position_ids": (cos, sin),
    "past_key_values": padded_past_key_values,
}
```

纯文本模式会把：

```python
"inputs_embeds"
```

替换为：

```python
"input_ids"
```

`separate_tuple_input_output=False` 时，KV 使用 PyTorch 模型原生的嵌套 tuple；prepare/QuantSim/ONNX 路径使用 `True` 时，会把各层 K/V 展平为独立输入输出，以满足静态图签名要求。

### 4.9 第八步：执行真正的模型

```python
outputs = self.model(**prepared_inputs)
```

这里的 `self.model` 是外层：

```text
Qwen2ForCausalLM
```

它内部还有一个同名成员：

```text
Qwen2ForCausalLM.model = Qwen2Model
```

完整调用链为：

```text
nn.Module.__call__
  └─ Qwen2ForCausalLM.forward
       ├─ Qwen2Model.forward
       │    ├─ Qwen2DecoderLayer × 36
       │    │    ├─ QcAttention.forward_conv
       │    │    └─ MLP_forward_conv
       │    └─ final RMSNorm
       └─ lm_head_conv → logits
```

由于 `inputs_embeds` 已提供，语言模型的 `embed_tokens(input_ids)` 会被绕过。Attention、MLP 和 lm_head 则已经被 `prepare_conv()` 换成数学等价的 1×1 Conv 实现。

模型内部的 Attention 在这里完成：

1. 当前 hidden 生成 Q/K/V；
2. 当前 Q/K 应用 RoPE；
3. 当前 K/V 与传入的历史 KV 一起参与 Attention；
4. 当前新 K/V 写入 `DynamicCache`；
5. 产生本层 Attention 输出。

因此“更新新 KV”的原始动作发生在每层 Attention 中；FPM 的输出阶段负责裁剪、合并和管理这些 K/V。

### 4.10 第九步：按 `input_length` 截取有效 logits

模型固定返回最多 `ARN` 个位置的 logits：

```text
[B, 1073, vocab_size]
```

FPM 不按 attention mask 逐元素筛选，而是使用补齐前记录的 `input_length`：

```python
lm_logits = outputs[0]
lm_logits = lm_logits[:, -info["input_length"]:, :]
```

例如：

```text
模型输出：[73 个 dummy logits | 1000 个有效 logits]
截取结果：                  [1000 个有效 logits]
```

必须区分：

```text
mask          = 计算过程中不让有效 token 关注 dummy/未来
input_length  = 计算结束后真正裁掉左侧 dummy 输出
```

如果 mask 中间存在其他 0，当前这段代码也不会把中间 logits 删除；它只保留最后 `input_length` 个位置。

### 4.11 第十步：整理并返回有效 KV Cache

当前配置：

```yaml
return_new_key_value_only: true
```

模型侧主要输出当前块新生成的 K/V。FPM 随后完成：

1. 根据 `input_length` 删除当前输入左 padding 对应的新 KV；
2. 从 `prepared_inputs` 取回包含 dummy 的旧 KV；
3. 拼接旧 KV 与有效新 KV；
4. 根据 `kv_padding_length` 去掉旧 KV 前面的 dummy；
5. 返回只包含真实历史的逻辑 KV Cache。

可以表示为：

```text
模型输入旧 KV： [dummy_old | real_old]
模型输出新 KV： [dummy_current | real_current]

prepare_outputs：
  去掉 dummy_current
  拼接 old + current
  再去掉 dummy_old

最终返回：       [real_old | real_current]
```

返回结构统一为：

```python
{
    "lm_logits": valid_logits,
    "past_key_values": valid_past_key_values,
}
```

若外层还有下一块，`slice_inputs_and_run_successive_kvcache_inference()` 会把这里的 `past_key_values` 回传给下一次 FPM 调用。

## 五、当前配置下的形状总表

设：

```text
B = 1
L = 当前真实输入长度，L ≤ 1073
hidden_size = 2048
num_heads = 16
num_kv_heads = 2
head_dim = 128
```

主要张量形状为：

| 阶段 | 张量 | 典型形状 |
|---|---|---|
| dataloader 输出 | `input_embeddings` | `[B, L, 2048]` |
| 当前输入补齐后 | `inputs_embeds` | `[B, 1073, 2048]` |
| Past K 补齐后（转置存） | `past_key` | 每层 `[B, 2, 128, 975]` |
| Past V 补齐后 | `past_value` | 每层 `[B, 2, 975, 128]` |
| 外部 RoPE | `cos/sin` | 约 `[1, 1, 1073, 64]` |
| Combined mask | `attention_mask` | 约 `[B, 1, 1073, 2048]` |
| 模型固定输出 | `logits` | `[B, 1073, vocab_size]` |
| FPM 有效输出 | `lm_logits` | `[B, L, vocab_size]` |
| 当前有效新 K | `new_key` | 每层 `[B, 2, 128, L]` |
| 当前有效新 V | `new_value` | 每层 `[B, 2, L, 128]` |

`约`表示具体 batch 轴广播形式可能因 RoPE/mRoPE 分支略有不同，但序列长度关系不变。

## 六、这条通用路径在哪些阶段复用

### 6.1 原始浮点模型 PPL

```text
test_dataloader
  → slice 分块
  → orig_fpm
  → 原始浮点 logits
  → CrossEntropyLoss
  → orig_ppl
```

### 6.2 prepare 后模型验证

prepared model 改为扁平输入输出签名，但仍由 FPM 负责生成相同语义的 mask、RoPE 和 KV，从而检查模型 prepare 是否改变数值结果。

### 6.3 QuantSim / calibration

量化模拟模型仍需要固定形状输入。FPM 保证校准和量化后评估走的输入语义，与浮点基线一致。

### 6.4 ONNX / 端侧运行

导出的定长模型图只包含固定 shape 的核心计算。真实端侧运行时需要承担与 FPM 同等的外围职责：维护历史 KV、构造 mask/RoPE、组织固定输入并处理模型输出。

因此 FPM 可以理解为“Python 侧的端侧运行时参考实现”。它本身通常不是要整体导进 ONNX 的网络层。

## 七、容易混淆的问题

### 7.1 `prepare_inputs()` 是否属于模型计算图

不是。它是调用 `self.model(...)` 之前的 Python 外围逻辑。真正模型图从准备好的固定输入开始。

### 7.2 padding 的无效 logits 是靠 mask 删除的吗

不是：

- mask 在 Attention 计算期间屏蔽 dummy 和未来位置；
- `input_length` 在模型输出后截取有效 logits。

### 7.3 KV Cache 是在 `prepare_outputs()` 才生成的吗

不是。每层 Attention 先生成当前 K/V；`prepare_outputs()` 负责去 dummy、拼历史和恢复逻辑缓存。

### 7.4 每次 FPM 调用都是 decode 吗

不是。PPL 中一块可以并行处理几百或 1073 个真实 token，更接近分块 prefill。只有真实生成时“每次把自己刚生成的 token 再喂回模型”才是自回归 decode。

### 7.5 `context_length=2048` 是否表示当前输入也是 2048

不是。当前图的分工是：

```text
Past 975 + Current 1073 = Total 2048
```

### 7.6 FPM 会重新执行视觉编码器吗

不会。多模态 dataloader 已经生成并融合 image embedding；FPM 和 `Qwen2ForCausalLM` 这里只运行语言模型部分。

### 7.7 `prepare_inputs` 和 AIMET prepare 是一回事吗

不是：

| 名称 | 作用 |
|---|---|
| `FPM.prepare_inputs()` | 每次运行前整理输入张量 |
| QAIRT/AIMET Prepare | 后续阶段转换/规范化模型图，便于量化与导出，见 [06 主篇](./06-Prepare模型准备阶段.md) |

---

## 八、记忆锚点

```text
FPM = 模型外的“变长 ↔ 定长”适配器
```

- 调用顺序只有三步：`prepare_inputs → model → prepare_outputs`。
- `ARN=1073` 是当前输入槽位，`975` 是历史 KV 槽位，总上下文为 `2048`。
- `prepare_inputs`：补当前输入、补 Past KV、算位置/RoPE、合并 mask。
- `model`：Decoder Layer × N → final norm → lm_head，同时在 Attention 中产生新 KV。
- `prepare_outputs`：按 `input_length` 裁 logits/新 KV，按 `kv_padding_length` 去旧 KV dummy，再合并有效缓存。
- mask 负责“算的时候看不见”，长度记录负责“算完后真正裁掉”。
- 长序列由 `slice_...inference` 分块，块间传 KV，最后拼 logits。
- FPM 是 PPL、prepare 后验证、QuantSim 和端侧固定图之间的共同数据通路。
