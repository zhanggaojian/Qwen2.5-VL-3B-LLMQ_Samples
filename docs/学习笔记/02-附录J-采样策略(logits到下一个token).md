# 附录 · 采样策略：从 logits 到下一个 token

> **关联**：接在 [附录I(层结构)](./02-附录I-层结构-Norm与残差.md) 和 [总结篇](./02-模型适配总结篇-结构与替换全景.md) 之后——模型跑到 `lm_head` 输出 logits 就结束了，这篇讲"**logits 之后怎么变成下一个词**"。
> **前置地基**：懂 `lm_head` 输出的是词表分数 logits → [总结篇第一节](./02-模型适配总结篇-结构与替换全景.md)。
> **一句话本质**：`lm_head` 只给出"每个词的分数(logits)"，**softmax 变概率、再按某种策略挑一个词**，这一步就是采样；两大流派——**取最大（确定性）** 和 **随机采样**——在"稳定"和"多样"之间权衡，主流是 **温度 + top-p(+top-k) + 重复惩罚** 的组合拳。
>
> ⚠️ **本项目不做采样**（见第四节）：量化脚本只算 PPL、导出 logits，采样发生在端侧运行时。这篇是补全"生成"全貌的背景知识。
>
> **本篇结构（四段式）**：一 介绍（这一步在哪、为什么要采样）→ 二 原理（两大流派与各自方法）→ 三 官方/通用做法（常用组合与 Qwen 默认参数）→ 四 本项目改造后的做法（为什么"不采样"）。

---

## 一、介绍：先定位这一步在哪（从 logits 到下一个 token）

```
DecoderLayer × N → final norm → lm_head → logits [vocab] ──softmax──▶ 概率分布 ──采样──▶ 下一个 token
                                          每个词一个分数                                    ↑ 本篇讲这里
```

- **logits**：`lm_head` 输出，长度 = 词表大小（如 15 万），每个词一个"原始分数"，可正可负、未归一化。
- **softmax**：把 logits 变成加和为 1 的概率分布。
- **采样(decoding/sampling)**：按某种规则从这个分布里挑出下一个词。

自回归生成就是"挑一个词 → 拼到输入末尾 → 再算下一个"循环往复，所以**每一步都要采样一次**。

---

## 二、原理：两大流派与各自方法

采样的"原理"就是**先把 logits 变成概率分布，再按某种规则挑词**。所有方法先归成两大流派（取最大 / 随机采样），再各自细分。

### 2.1 两大类：取最大（确定性） vs 随机采样

所有采样方法都可以先归成两大类，再往下细分：

| | 类别一：取最大 / 确定性 | 类别二：随机采样 |
|---|----------------------|-----------------|
| 怎么选 | 选**分数/概率最高**的 | 按概率**加权随机抽签** |
| 同输入同输出？ | ✅ 是（可复现）| ❌ 否（每次可能不同）|
| 代表方法 | **贪心(argmax)**、**Beam Search** | **温度 / top-k / top-p** 修整分布后采样 |
| 特点 | 稳定、可复现、易重复乏味 | 多样、有创意、可能出错 |
| 适合 | 翻译/摘要/代码/要复现 | 聊天/创作/头脑风暴 |

#### 2.1.1 "随机采样"到底是什么

随机采样 = **按概率大小做"加权抽签"**，不是每次都选最大的那个。比如分布 `the:0.5, a:0.3, cat:0.2`，就像转一个转盘，各词占的面积等于它的概率：

```
├──────the (50%)──────┼────a (30%)────┼──cat (20%)──┤
0                    0.5             0.8            1.0
        随机丢一个 0~1 的点，落在哪段就选哪个词
```

- **大概率**落在 the，但也有 30% 选 a、20% 选 cat；
- 所以**同样输入多跑几次会得到不同的词**（技术名：multinomial 多项式采样）。
- 对比"取最大(argmax)"：那个**永远只选 the**，毫不随机。

#### 2.1.2 两类其实是连续的

调参数能让"随机采样"退化成"取最大"：

- 温度 `T → 0`：分布无限尖 → 几乎必中最高分词 → **等于贪心**；
- `top-k = 1`：只留 1 个词、别无选择 → **等于贪心**。

所以贪心可看成随机采样"最保守"的特例。实际就是用温度、top-p 这些旋钮，在"完全确定"和"很随机"之间连续调节。

---

### 2.2 类别一：取最大 / 确定性

#### 2.2.1 贪心解码（Greedy / argmax）

每步直接选概率最高的那个词（`argmax`）。

- ✅ **确定性**（同输入必得同输出）、**最快**、实现最简单。
- ❌ 输出**单调、重复、乏味**，容易陷入死循环（"很好很好很好…"）；只顾当前一步最优，可能错过整体更优的句子。

> 适合：要可复现、要稳定的场景（调试、单元测试、部分代码生成）。

#### 2.2.2 束搜索（Beam Search）

每步不止留 1 个，而是保留概率最高的 **B 条候选序列**（beam width = B），一路并行扩展，最后选整条序列联合概率最高的。

- ✅ 比贪心更"全局"，对**有标准答案**的任务好：机器翻译、摘要、代码补全。
- ❌ 计算/显存 ×B 倍；对**开放式生成**反而更**平淡、通用、易重复**（联合概率最高 ≠ 最有趣）；有长度偏置（偏爱短句），需额外惩罚。

> 直觉：beam search 找"最可能"的话，但人类觉得好的文本往往不是最高概率的那句。所以聊天/创作很少用它。

**为什么计算量是 ×B**：不是"把 B 个词塞进同一条序列"，而是**同时维护 B 条各自独立的序列（beam），每步给每一条都跑一次模型**：

```
贪心    ：1 条序列 → 每步 1 次前向 → 选 1 个词
Beam(B)：B 条序列 → 每步 B 次前向 → 从 B×V 个扩展里剪枝回 B 条
```

- **前向 ×B**（主要开销）、**KV Cache ×B**（每条 beam 各存一份历史）、每步还要在 `B×V` 个候选里选 top B。

**"联合概率"体现在哪**：一句话的联合概率 = 每步条件概率的连乘（链式法则）：

$$
P(w_1 w_2 \dots) = P(w_1)\cdot P(w_2\mid w_1)\cdot P(w_3\mid w_1 w_2)\cdots
$$

每条 beam 都携带一个**累积分数**，就是它到目前为止的联合概率；每步扩展时 `新分数 = 旧分数 × P(新词|前文)`，排序挑 top B 比的就是它。举例（B=2）：

```
beam1 "the cat" 联合=0.4 → sat:0.6, ran:0.3
beam2 "the dog" 联合=0.3 → ran:0.5, barked:0.4

扩展 = 旧联合 × 新词概率：
the cat sat = 0.4×0.6 = 0.24 ★   the dog ran = 0.3×0.5 = 0.15 ★
the cat ran = 0.4×0.3 = 0.12     the dog barked = 0.3×0.4 = 0.12
→ 留 top2：the cat sat(0.24)、the dog ran(0.15)
```

**这就是 Beam 胜过贪心的关键**：贪心只看当前一步最大，Beam 比整句联合概率，能容忍"某步不是最大、但整句更优"的路径：

```
第1步 A:0.5 / B:0.4  → 贪心锁 A
但 A 后续最好只 0.2 → 联合 0.5×0.2=0.10
   B 后续有 0.8     → 联合 0.4×0.8=0.32 ★贪心永远得不到
```

> 实现细节：概率连乘会浮点下溢，工程上取对数把"连乘"变"**log-prob 累加**"：$\log P = \sum_i \log P(w_i\mid w_{<i})$，单调性不变、数值更稳。

### 2.3 类别二：随机采样

随机采样这一大类，本身就是 2.1.1 讲的"按概率加权抽签"。但如果直接对原始分布抽，长尾里几万个离谱词加起来也有不小概率、偶尔会蹦出乱词。所以下面的温度、top-k、top-p 都是**抽签前的"修整分布"步骤**——调陡调平、砍掉长尾——最后才落到那一步随机抽。

```
logits ─÷温度T─→ 调分布陡平 ─top-k/top-p─→ 砍掉长尾 ─→ 归一化 ─→ 【随机采样抽一个】
                                                                  ↑ 真正"选词"在这
```

#### 2.3.1 温度（Temperature）—— 创造力旋钮

在 softmax **之前**把 logits 除以温度 T：

$$
p_i = \text{softmax}\!\left(\frac{\text{logits}}{T}\right)
$$

- `T < 1`：分布变**尖** → 更保守、更接近贪心；
- `T > 1`：分布变**平** → 更随机、更有创意；
- `T → 0`：退化成**贪心**；`T = 1`：原始分布。

**数字例子**：设 3 个词 logits = `A:2.0, B:1.0, C:0.0`，先 `÷T` 再 softmax：

| T | ÷T 后 logits | softmax 后 `[A,B,C]` | 效果 |
|---|-------------|----------------------|------|
| 0.5（低温）| `[4, 2, 0]` | `[0.87, 0.12, 0.02]` | **更尖** → 保守，几乎只选 A（接近贪心）|
| 1.0（原始）| `[2, 1, 0]` | `[0.66, 0.24, 0.09]` | 原样 |
| 2.0（高温）| `[1, 0.5, 0]` | `[0.51, 0.31, 0.19]` | **更平** → 随机，B/C 也很有机会 |

温度**本身不选词**，只把分布调陡或调平，调完照常按新分布随机采样：

- 要**稳定/少出错**（代码、事实问答）：**低温** 0.2~0.7；
- 要**创意/多样**（写故事、头脑风暴）：**高温** 1.0~1.3。

> 直觉：低温像"精英赛"，实力稍强就几乎必胜；高温像"抽奖会"，弱者也能翻盘；T→0 直接钦定第一名（贪心）。

#### 2.3.2 截断类：top-k 与 top-p

核心思想：**先把不靠谱的长尾词砍掉，只在"靠谱的一小撮"里随机采**。两者区别只在**怎么决定"留几个"**。用同一个分布（按概率从高到低排好）对比：

```
词      概率     累积概率
the    0.40      0.40
a      0.25      0.65
cat    0.15      0.80
dog    0.10      0.90
car    0.05      0.95
...    (后面还有几万个词，每个概率都极小)  ...
```

##### Top-k 采样：固定留 k 个

只保留概率最高的 **k 个**词，其余全丢，再**重新归一化**后在这 k 个里随机采。以 **k=3**：

```
保留前 3 个：the(0.40), a(0.25), cat(0.15)；丢掉 dog、car 及之后所有词
归一化（÷三者之和 0.80）：the=0.50, a=0.31, cat=0.19
→ 在 {the,a,cat} 里按 [0.50,0.31,0.19] 随机抽一个
```

> **为什么要"重新归一化"**：砍掉一些词后剩下的概率加起来不到 1，要按比例放大到重新加和为 1，才能当概率来采样。

- ✅ 简单，砍掉长尾垃圾词。
- ❌ k 是**固定值、不看分布形状**：分布很尖时 k 太大会把几乎不可能的词也拉进来（噪声）；分布很平时 k 太小又砍掉很多合理的词（限制多样性）。

##### Top-p / 核采样（Nucleus Sampling）★最常用

从高到低**累加概率，凑够阈值 p 就停**，只保留这批词（叫"核 nucleus"），归一化后采样。以 **p=0.9**：

```
the  累积 0.40
a    累积 0.65
cat  累积 0.80
dog  累积 0.90  ← 达到 0.9，停！
------ 只保留 {the,a,cat,dog}，car 及之后全丢 → 归一化后采样 ------
```

**留几个不是固定的，由分布自己决定**——凑够 90% 概率质量需要几个就留几个。

- ✅ **候选集大小自适应**：分布尖时自动只留几个、分布平时自动留更多——这是它比 top-k 强的关键。
- ❌ 需要排序 + 算累积；p 要调。**开放式生成的事实标准。**

##### 核心区别：按"个数"切 vs 按"累积概率"切

```
Top-k (k=3)：  ✂ 数着数留 3 个，不管概率够不够
   the  a  cat │ dog car ...        ← 固定切在第 3 个后面
Top-p (p=0.9)：✂ 累加到 90% 才切，够几个留几个
   the  a  cat  dog │ car ...       ← 切在"累积刚过 0.9"处（这里第 4 个）
```

两个极端最能体现 top-p 的好：

| 分布情况 | Top-k(k=5) | Top-p(p=0.9) |
|---------|-----------|--------------|
| **很尖**（1 个词占 95%）| 硬留 5 个，后 4 个是噪声 ❌ | 只留 1 个，干净 ✅ |
| **很平**（前 30 个都合理）| 只留 5 个，太死板 ❌ | 留够 ~30 个，多样 ✅ |

> top-k 和 top-p 常**一起用**（先 top-k 粗砍到 k 个，再 top-p 精砍到核），再叠加温度。

#### 2.3.3 其它常见修正

- **重复惩罚（repetition penalty）**：给已经出现过的词降权，压制"复读机"。
- **no_repeat_ngram**：禁止重复出现的 n-gram。
- **min-p / typical sampling**：更新的自适应截断变体，按分布形状动态定阈值。

## 三、官方 / 通用做法：常用组合与 Qwen 默认参数

实践中几乎都是**组合拳**：`温度 + top-p (+ top-k) + 重复惩罚`。

| 场景 | 常用配置 |
|------|---------|
| 开放式聊天 / 创作 | `T≈0.7~1.0` + `top_p≈0.8~0.95`（+ 小 `top_k`）+ 轻微重复惩罚 |
| 要稳定 / 可复现 / 代码 | 贪心，或低温 `T≈0.0~0.3` |
| 翻译 / 摘要（有标准答案）| Beam Search 或低温 |

以 **Qwen** 官方默认生成参数为例（大致）：`temperature=0.7`、`top_p=0.8`、`top_k=20`、`repetition_penalty=1.05` —— 典型的"温度 + top-p + top-k + 重复惩罚"。

### 方法速查表

| 方法 | 大类 | 随机性 | 优点 | 缺点 | 适合 |
|------|------|--------|------|------|------|
| 贪心 argmax | 取最大 | 无 | 快、确定、简单 | 重复、乏味、易循环 | 复现、部分代码 |
| Beam Search | 取最大 | 无 | 全局更优 | 贵、开放生成平淡 | 翻译、摘要 |
| 温度 | 随机采样(预处理) | 可调 | 控制创造力 | 单用不截断有长尾噪声 | 配合截断用 |
| Top-k | 随机采样(预处理) | 有 | 砍长尾、简单 | k 固定不自适应 | 配合温度 |
| **Top-p/核** | 随机采样(预处理) | 有 | **自适应、质量多样兼顾** | 需排序、调 p | **开放式生成主流** |

## 四、本项目改造后的做法：为什么"不采样"

这个仓库是**量化 + 导出**流程，不是"生成文字"流程。它对 logits 只做两件事：

**1. 算 PPL（困惑度）评估精度——用交叉熵，不采样：**

```166:176:example1/llm_quant.py
        shift_logits = lm_logits[..., :-1, :].contiguous().to(dtype=torch.float32)
        shift_labels = batch['input_ids'][..., 1:].contiguous().to(shift_logits.device)
        loss_fct = CrossEntropyLoss()
        loss += loss_fct(
            shift_logits.view(-1, shift_logits.size(-1)),
            shift_labels.view(-1),
        ).item()
    loss = loss / num_batches
    ppl = loss.exp()
    return ppl
```

PPL 是拿 logits **直接和"真实的下一个词"比对**算交叉熵、再取 exp，衡量"模型对真实文本有多惊讶"，**全程不采样**——不需要真的生成词，只看模型给正确词打了多高分。这是量化前后对比精度的标准手段（本项目要求量化后 PPL 与原模型差 < 1e-4）。

下面把这段代码彻底拆开。

#### (a) 直觉：PPL 在量什么

一句话：**PPL 衡量"模型看到真实文本时有多惊讶"**。

- 你手里已经有一段**真实、正确**的文本（wikitext 语料），比如 `The cat sat on mat`。
- 把它喂给模型，在每个位置问："下一个词是啥？给每个候选词打个分。"
- 你**已经知道正确答案**（下一个词真的是什么），于是看模型给"那个正确词"打的分高不高：
  - 给正确词打高分 → 不惊讶 → PPL 低 → 好；
  - 给正确词打低分 → 很惊讶 → PPL 高 → 差。

关键：**因为正确答案是现成的，根本不需要模型自己"生成"一个词**——只是核对"模型对已知正确词的信心"。这就是"不采样"的根本原因。

#### (b) "生成"和"评估 PPL"的区别

| | 生成文字（前面讲的采样）| 算 PPL（这节）|
|---|---|---|
| 下一个词从哪来 | 模型自己**造**（softmax→采样挑一个）| 语料里**本来就有**，直接读 |
| 需要 softmax/采样吗 | 需要，要挑一个词出来 | **不需要**，logits 和正确答案对比即可 |
| 目的 | 产出新内容 | 打分：模型对真实文本拟合有多好 |
| 结果确定吗 | 随机采样每次可能不同 | **完全确定**（适合量化前后对比）|

#### (c) 为什么要 shift（错位一格再对齐）★关键

模型是**自回归**的：第 `i` 个位置输出的 logits，预测的是**第 `i+1` 个词**。这就是"错位"的来源。以 `input_ids = [The, cat, sat, on, mat]`（位置 0~4）为例：

```
位置0 (输入 The) → logits₀ 预测"The 后面" → 理想答案 cat
位置1 (输入 cat) → logits₁ 预测"cat 后面" → 理想答案 sat
位置2 (输入 sat) → logits₂ 预测"sat 后面" → 理想答案 on
位置3 (输入 on)  → logits₃ 预测"on 后面"  → 理想答案 mat
位置4 (输入 mat) → logits₄ 预测"mat 后面" → ??? 没答案，作废
```

想把"模型预测 ↔ 真实答案"配对，就得砍两刀让它们对齐：

- **`shift_logits = lm_logits[..., :-1, :]`**：logits **砍掉最后一个**（logits₄ 预测的是不存在的下一个词，没答案可对）。
- **`shift_labels = input_ids[..., 1:]`**：答案 **砍掉第一个**（开头的 The 是给定输入，不是任何位置的预测目标）。

砍完两者都剩 4 个，天然一一对齐：

```
索引:            0        1        2        3
shift_logits:  logits₀  logits₁  logits₂  logits₃
shift_labels:   cat      sat      on       mat
                完美配对：每个预测都对上了它该预测的真实词
```

> 一句话记忆：**模型第 `i` 位预测第 `i+1` 个词 → logits 去尾、labels 去头，剩下正好对齐。**

#### (d) 切片语法 `lm_logits[..., :-1, :]`

`lm_logits.shape = [batch, seq_len, vocab_size]`，方括号里逗号分成 3 段依次对应这三个维度：

```
[  ...  ,  :-1  ,  :  ]
  batch    seq    vocab
  全要   去掉最后  全要
        一个位置
```

- `...`（Ellipsis 省略号）：前面所有维度**原样全保留**（这里指 batch），等价于 `:`，好处是不管前面有几维都能兜住。
- `:-1`：切片，`-1` 指最后一个，`:-1` = 从头取到倒数第二个 → **扔掉最后一个**（作用在 seq_len 上）。
- `:`：这一维**整个都要**（作用在 vocab 上，每个词的打分都保留）。

形状变化：`[1, 128, 151936] → [1, 127, 151936]`，只有序列维 128→127。

同理 `input_ids[..., 1:]`：`1:` = 从第 1 个取到末尾 → **去头**，`[The,cat,sat,on,mat] → [cat,sat,on,mat]`。

切片速查：

| 写法 | 含义 |
|------|------|
| `:` | 这一维全要 |
| `:-1` | 去掉最后一个 |
| `1:` | 去掉第一个（去头）|
| `:3` | 只要前 3 个（0,1,2）|
| `-1` | 只要最后一个（会降维）|
| `...` | 没写到的维度全部原样保留 |

> `.contiguous()` 和 `.to(float32)` 与对齐逻辑无关：前者是切片后让内存重新连续（后面 `view` 拍平要求连续内存），后者是把精度提到 32 位让 loss 算得更稳，理解时可忽略。

#### (e) CrossEntropyLoss 与最后的 exp

`CrossEntropyLoss(logits, 正确词)` 等价于：对 logits 做 softmax → 取**正确词**的概率 `p` → 算 `-log(p)`。只用到正确词的概率，所以完全不需要"挑词"，也就没有采样。

最后 `ppl = loss.exp()`：**PPL = exp(平均交叉熵)**，取 exp 后有个直观解释——

> **PPL ≈ 模型每一步"平均在多少个词里纠结"。**

- PPL=1：完美，每步 100% 确定正确词；
- PPL=10：相当于每步在"约 10 个等可能的词里猜"；
- 越大越困惑越差。数学上若每个正确词概率为 `p`，则 `PPL = exp(-log p) = 1/p`，即"正确词概率的倒数"。

项目里就是比 `|PPL_orig - PPL_quant| < 1e-4`，因为 PPL 是**确定性数字**，能精确对比量化前后掉了多少精度（见文件 424~427 行的断言注释）。

**2. 导出 ONNX，输出就叫 `logits`：**

```345:345:example1/llm_quant.py
    output_names = ['logits'] + _get_past_key_values_names('out', llm_config.num_hidden_layers)
```

**导出的模型只吐 logits 就结束了。** softmax + 采样是**端侧 App / 运行时框架**拿到 logits 后自己做的，策略由部署方决定，不在量化脚本里。

```

算 PPL(交叉熵) 评估质量                softmax → 温度/top-k/top-p → 采样
导出 ONNX，输出 logits                        → 下一个 token
```

## 五、记忆锚点

- 两大类：**① 取最大/确定性**（贪心、Beam Search，挑最优、可复现）；**② 随机采样**（按概率加权抽签，多样、每次可能不同）。
- **随机采样**=转盘加权抽签；温度/top-k/top-p 是它的**预处理**（修整分布），不是独立第三类；`T→0` 或 `top-k=1` 会退化成贪心 → 两类连续可调。
- 顺序：**logits →（温度）→ softmax → 截断(top-k/top-p) → 随机采样 → 下一个 token**。
- **温度** = 创造力旋钮（<1 保守、>1 发散、→0 贪心）。
- **top-k** 按个数固定截断；**top-p/核采样按累积概率自适应截断**，是开放式生成主流。
- 常用组合：**温度 + top-p(+top-k) + 重复惩罚**；Qwen 默认约 `T=0.7, top_p=0.8, top_k=20`。
- **本项目不采样**：只算 PPL + 导出 logits，采样在端侧运行时做。
- 一句话：**模型只负责给分（logits），采样负责在"稳定(取最大)"和"有趣(随机)"之间挑一个词——这一步不在量化脚本里，在部署端。**
