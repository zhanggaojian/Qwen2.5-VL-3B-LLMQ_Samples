## 三、按多头结构分 ⭐⭐最高频（KV Cache 优化主线）

核心区别：**Q 有几个头、K/V 有几个头**。K/V 头越少 → KV Cache 越小、推理越省。

| 类型 | 全称 | Q 头 | K/V 头 | KV Cache | 代表 |
|------|------|------|--------|----------|------|
| **MHA** | Multi-Head Attention | h | **h** | 最大 | 原版 Transformer、GPT-2 |
| **MQA** | Multi-Query Attention | h | **1** | 最小(省 h 倍) | PaLM、Falcon |
| **GQA** | Grouped-Query Attention | h | **g**(1<g<h) | 折中 | **Qwen2**、Llama2-70B |
| **MLA** | Multi-head Latent Attention | h | 压成**低秩潜向量** | 极小且性能好 | DeepSeek-V2/V3 |

```
MHA:  Q1 Q2 Q3 Q4      MQA:  Q1 Q2 Q3 Q4      GQA:  Q1 Q2 | Q3 Q4
      K1 K2 K3 K4            K1(共享)               K1   |  K2
      V1 V2 V3 V4            V1(共享)               V1   |  V2
   每个Q配独立KV          所有Q共享1组KV         分组共享(此处2组)
```

**面试要点**：
- MQA/GQA 解决的核心痛点是 **KV Cache 占显存 + 访存带宽**（推理瓶颈常在访存不在算力）。
- GQA 是 MHA(g=h) 和 MQA(g=1) 的**统一折中**：质量接近 MHA，开销接近 MQA。
- Qwen2 用 GQA：`num_heads`(Q多) > `num_key_value_heads`(KV少)，用 `repeat_kv` 把 KV 复制对齐再算（见 [附录A 2.4](./02-附录A-Attention注意力机制.md)）。
- MLA(DeepSeek) 进一步把 K/V 压成一个低秩潜向量再缓存，KV Cache 更小。

### 三·补A · 三者的 QKV 张量形状（面试常追问）

以 `hidden=2048 = head_num(16) × head_dim(128)` 为例：

| 张量 | MHA | GQA(g=2) | MQA |
|------|-----|----------|-----|
| Q | `[b, 16, s, 128]` | `[b, 16, s, 128]` | `[b, 16, s, 128]` |
| K | `[b, 16, s, 128]` | `[b, 2, s, 128]` | `[b, 1, s, 128]` |
| V | `[b, 16, s, 128]` | `[b, 2, s, 128]` | `[b, 1, s, 128]` |

**Q 永远是满头(16)；区别全在 K/V 的头数（16 / g / 1）。**

> **为什么这张表没有 MLA？** 因为 MHA/MQA/GQA 是**同一个范式**——缓存的都是"每头真实 K/V"，只在**头数**（16/g/1）上滑动，能并排列进同一张形状表。而 **MLA 换了另一根轴**：不按头缓存 K/V，而是把 K/V **压缩成一个低秩潜向量**再存，缓存的东西根本不是 `[b, 头数, s, head_dim]` 这种形状，所以放不进这张"改头数"的表。详见下面 三·补D。

### 三·补B · 头数到底由谁决定？(reshape 还是权重维度) ⭐易混

一条统一规则：**头数 = 投影层输出维度 ÷ head_dim**，且必须 `头数 × head_dim = 输出维度`。

关键在**三个投影层的输出维度**：

```
q_proj 输出 = head_num × head_dim = 2048  → reshape [b,s,16,128] → 16 头
k_proj 输出 = ?                            → 决定 K 有几个头
v_proj 输出 = ?                            → 决定 V 有几个头
```

| | q_proj 输出 | k/v_proj 输出 | K/V 头数 | 头数由谁定 |
|---|---|---|---|---|
| MHA | 2048 | **2048(同 Q)** | 16 | **reshape/config**：输出给够，`num_heads` 超参决定切几份(2048 可切 16×128 也可 8×256) |
| GQA | 2048 | **256(=2×128)** | 2 | **权重维度卡死**：只有 256，最多切 2 头 |
| MQA | 2048 | **128(=1×128)** | 1 | **权重维度卡死**：只有 128，只能 1 头 |

- **MHA**：Q/K/V 投影输出维度都是 hidden，光看权重看不出头数 → 头数是 config 的 `num_heads`，在 **reshape 那步切出来**（2048 里没写"我是几头"）。
- **MQA/GQA**：故意把 `k_proj/v_proj` 输出**砍小**（`k_proj` 权重从 `[2048,2048]` 缩成 `[128,2048]`/`[256,2048]`），物理上 reshape 就切不出更多头 → 头数被**权重维度卡死**。

> ⚠️ 纠一个常见误解：**不是"先都 reshape 成 16 头，再把 K/V 压成 1 头"**。K/V 从投影输出就只有 1 个头的量(128)，reshape 只是"按已有大小切开"，切不出多余的头。**reshape 负责切，权重维度负责能切出的上限。**

#### 三·补B2 · 权重矩阵长什么样 + 完整维度流水

投影层就是 Linear，做 `输出 = 输入 × W^T`。**PyTorch 里权重形状是 `[out, in]`**：`in` 永远=hidden(输入不变)，`out = 头数 × head_dim`(决定能 reshape 出几个头)。

| 投影 | out 维度 | 权重形状 `[out,in]` | reshape 成 |
|------|---------|--------------------|-----------|
| `q_proj` | 16×128=2048 | `[2048, 2048]` | `[b,s,16,128]` |
| `k_proj`(MHA) | 16×128=2048 | `[2048, 2048]` | `[b,s,16,128]` |
| `k_proj`(GQA,2头) | 2×128=256 | `[256, 2048]` | `[b,s,2,128]` |
| `k_proj`(MQA) | 1×128=128 | `[128, 2048]` | `[b,s,1,128]` |

**Q 的完整流水（16 头）**：
```
hidden [b,s,2048] ──× W^T([2048,2048])──▶ [b,s,2048] ──reshape 2048→(16,128)──▶ [b,s,16,128]
```

**MQA 的 K 完整流水（1 头）**——关键看最后 reshape：
```
hidden [b,s,2048] ──× W^T([2048,128])──▶ [b,s,128] ──reshape 128→(1,128)──▶ [b,s,1,128]
                       ↑ out=128, 压成128维         ↑ 只有128个数, 只能切1个头
```

- 矩阵乘先把 hidden 压到 **out 维度**（Q→2048、MQA的K→128）。
- 再 reshape 把 out **切成 (头数, head_dim)**：`2048→(16,128)`、`128→(1,128)`。**有多少个数决定能切几个头。**
- 那个 "1" 头维**不能省**：要留着才能和 Q 的 `[b,16,s,128]` 对齐做广播(见 三·补C)。

> ⭐ 关键：**权重矩阵本身不含"头"的概念**（`[2048,2048]` 里没写几个头），头是 reshape 切出来的。等价地看，`[2048,2048]` 可视为 16 个头各自 `[128,2048]` 小投影**拼起来**——所以"每个头有自己的 Q/K/V"在概念上也对。

### 三·补C · K/V 头少，怎么和满头 Q 相乘？

算 `QK^T` 时 Q 有 16 头、K 只有 1 或 2 头，对不上，两种等价做法把 K/V "补齐"到 16：

| 机制 | 做法 | 用在 |
|------|------|------|
| **广播 broadcast** | K/V 的 head 维是 1，matmul 时自动复用给每个 Q 头（不真复制数据，省内存） | MQA(head=1 天然可广播) |
| **`repeat_kv`** | 把 g 组 K/V **显式复制**到 head_num 个再 matmul | GQA(见 [附录A 2.4](./02-附录A-Attention注意力机制.md)) |

```
Q:   [b, 16, s, 128]
K^T: [b,  1, 128, s]  ──广播/repeat 1→16──▶ 每个Q头都用同一份K
QK^T:[b, 16, s, s]
```

> 本质：**KV Cache 只存少量头(1 或 g)省显存**；真正算的时候再临时补齐到满头。省的是"存储和访存"，不是"计算量"。

### 三·补C2 · GQA 具体怎么分组？（含"必须整除"）

**分组规则**：把 `num_heads` 个 Q 头**连续平均分成 g 组**，每组内的 Q 头共享该组唯一一份 K/V。

```
组数 g          = num_key_value_heads              (有几个 KV 头就有几组)
每组 Q 头数      = num_heads / num_key_value_heads  (代码里 = num_key_value_groups)
```

例：16 个 Q 头、2 个 KV 头 → 2 组、每组 8 个：

```
组0:  Q0~Q7   ──共享──▶ K0/V0
组1:  Q8~Q15  ──共享──▶ K1/V1     (连续切分：按顺序每 num_heads/g 个归一组)
```

**两端就是 MHA / MQA**：

| 组数 g | 每组 Q 头数 | 就是 |
|--------|-----------|------|
| g = num_heads | 1 | MHA（每 Q 头独享 KV） |
| 1 < g < num_heads | num_heads/g | GQA（折中） |
| g = 1 | num_heads | MQA（全部 Q 共享 1 份 KV） |

**⭐ 必须整除**：`num_heads` 必须能被 `num_key_value_heads` **整除**，否则分组不均、`repeat_kv` 没法按整数份复制。填了不整除的组合（如 16 配 3），**模型加载阶段直接报错**：

```python
if self.num_heads % self.num_key_value_heads != 0:
    raise ValueError("num_heads 必须能被 num_key_value_heads 整除")
n_rep = num_heads // num_key_value_heads   # repeat_kv 复制次数, 必须整数
```

> MHA(kv=heads) 和 MQA(kv=1) 都天然满足整除，是两个合法端点。常见合法组合：32/8(每组4)、64/8(每组8) 等。

### 三·补D · MLA 深入（DeepSeek，面试重点）

MHA/MQA/GQA 都是"**减头数**"；MLA(Multi-head Latent Attention) 是"**换成低秩压缩存储**"——不同范式，所以进不了上面那张形状表。下面数字以 DeepSeek-V2 为例。

> ⚠️ **别误解：MLA 仍然有 KV Cache，没被取消。** KV Cache 是"自回归生成时缓存历史、避免重算"的机制(见 [附录A 2.6](./02-附录A-Attention注意力机制.md)、[附录D](./02-附录D-自回归与自注意力.md))——这个 MLA 照样需要。变的只是**缓存里存什么**：MHA 存完整 K/V，MLA 存压缩后的 `c_KV + RoPE段`。**机制不变，存的内容变小了**，这正是它省显存的方式。decode 时照样"逐 token 追加 c_KV、读取历史"，只是每个格子装的是压缩向量。

#### 1. 核心：K/V 的低秩压缩（存潜向量、用时还原）

⚠️ **关键顺序（最易错）**：不是"先算出完整 K/V，再压缩 K/V"，而是**下投影直接作用在 hidden 上**，中间根本不产生完整 K/V：

```
存：hidden ──W_DKV(下投影,可学习)──▶ c_KV(潜向量, 如512维)   ← KV Cache 只存这个
                                        │(要用时)
用：c_KV ──W_UK(上投影)──▶ K
    c_KV ──W_UV(上投影)──▶ V           → 完整 K/V 只在算注意力这一刻临时还原, 从不存储
```

- 本质是**低秩分解**：原来的 `W_K` 被拆成 `W_UK × W_DKV`（矮胖 × 高瘦两个可学习矩阵）。
- **K、V 共享同一个 c_KV**（不是各压各的）→ 缓存里只存一份小向量。
- 完整 K/V **从不落盘**，只在用时升维；MHA 那种 `[b,头数,s,head_dim]` 的 K/V 在 MLA 里根本不进缓存。

#### 2. Q 的路径（不进缓存）

- Q **不缓存**，所以可当**普通投影 + reshape 成多头**理解：`hidden ──W_Q──▶ Q ──reshape──▶ [b,s,head_num,head_dim]`。
- DeepSeek 里 Q **也做了低秩压缩**（`hidden→c_Q→Q`），但目的是省**训练激活显存**，**不是**为 KV Cache，属可选的锦上添花。
- 记忆：**MLA 的省显存卖点只和 K/V 有关；Q 怎么算不影响缓存。**

#### 3. 解耦 RoPE（为什么缓存 = c_KV + RoPE 两部分）

**根因**：位置信息(RoPE) 没法塞进压缩通道，否则会毁掉"矩阵吸收"(见第4点)这个省显存的关键技巧。

- c_KV 里是**没有位置信息的纯内容**，理想情况只缓存它就够。
- 但 RoPE 是**按位置旋转**的。若把它加进 c_KV 的升维通道，`Q·K` 中间会夹进一个**随位置对 (m,n) 变化的旋转矩阵**：

```
Q·K = (Q那边) × R(位置差) × (c_KV那边)
                 ↑ 随每对位置变 → W_Q 和 W_UK 没法提前合并 → 矩阵吸收失效 → 优势没了
```

**解法：把 K/Q 各拆两段，位置信息单独走、单独缓存**

```
每个头的 K/Q = [ 内容段(d_h=128, 不带RoPE, 从c_KV升维→可吸收, 只缓存c_KV)
               ; RoPE段(d_R=64, 专门带RoPE, 所有头共享→直接缓存这一小段) ]
最终注意力分数 = 内容部分(用c_KV算) + 位置部分(用RoPE段算)，两块相加
```

- 所以缓存两样：**c_KV(压缩内容) + RoPE段 k_R(位置信息)** → 这就是"KV Cache = c_KV + RoPE"的由来。
- KV Cache = `c_KV(512) + RoPE段(64) = 576`，那个 **64 就是被迫单独拎出来的位置段**。
- 所以 MLA 里 `head_dim = d_h + d_R`（内容维+RoPE维），**不是简单的 hidden/head_num**。

> 一句话：**RoPE 会让矩阵吸收失效，没法融进压缩通道，只能把 K 拆成"可压缩的内容段(c_KV)"和"单独带位置的 RoPE 段"分别缓存**——所以是 c_KV + RoPE。

#### 3.5 RoPE 到底存在哪？（三者 vs MLA，面试常问）

**先看普通 MHA/MQA/GQA**：缓存的 K **已经带好 RoPE**。代码顺序是**先 RoPE、后进缓存**（[附录A 第三节](./02-附录A-Attention注意力机制.md) 官方源码逐段，第3步旋转 Q/K → 第4步 `past_key_value.update`）：

| 缓存内容(MHA/MQA/GQA) | 带 RoPE 吗 |
|----------------------|-----------|
| K | ✅ 带（存前已按自己位置旋转好） |
| V | ❌ 不带（V 从不做 RoPE，任何变体都一样） |

**为什么它们能直接烙、MLA 不能**：它们存的是**显式的真实 K**，旋转完直接存天经地义；MLA 存的是**压缩 c_KV(不是显式K)**，位置烙进去会破坏矩阵吸收 → 只能解耦。

**MLA 的 RoPE 段(k_R)怎么存**：

```
k_R = RoPE( W_KR · hidden )
        │        └ W_KR: 小的可学习投影, 把 hidden 压成 64 维
        └ RoPE: 按【该 token 位置】旋转(角度不可学, 只由位置定)
     → 加好 RoPE 后【直接存进缓存】(存法和普通K一样, 只是小且共享)
```

| MLA 缓存内容 | 维度 | 带 RoPE | 分头吗 |
|-------------|------|---------|--------|
| c_KV（内容） | 512 | ❌ | 共享一份 |
| k_R（位置段） | 64 | ✅ | **所有头共享一份** |

**⚠️ "所有头共享" ≠ "所有 RoPE 都一样"**（易错）：

| 维度 | k_R 一样吗 | 说明 |
|------|-----------|------|
| 跨 head（同 token 的 16 个头） | ✅ 一样(共享) | 位置是 token 的属性、与看它的头无关 → 共享不丢信息 |
| **跨 position（不同 token）** | ❌ **不一样** | 位置5的 k_R ≠ 位置6的 → **RoPE 要区分的正是位置，照样有用** |

- 位置是 token 自己的属性："第 5 个 token 在第 5 位"，哪个头看它都一样 → 位置信息没必要每头存一份，共享合理。
- **头之间的差异由内容段保证**：每个头用**各自不同的 W_UK** 从 c_KV 还原出不同的 K_C；k_R 共享只管统一注入"距离"。分工不冲突。

> 一句话：MHA/MQA/GQA 存"带好 RoPE 的真实 K"(V不带)；MLA 存"不带位置的 c_KV + 一小段带 RoPE 的共享 k_R"。k_R 跨头共享但**跨位置不同**，所以 RoPE 依然有效；多样性靠内容段。

#### 4. 矩阵吸收（推理时不用显式还原 K/V）

原理：`W_UK`、`W_UV` 是**固定矩阵**，利用"两个固定矩阵可提前乘成一个"，把 `W_UK` 合并进 `W_Q`（`W_UV` 合并进 `W_O`）。于是注意力分数 `= (x_q × 合并矩阵) · c_KV`，**式子里没有 K，不必把 c_KV 解压成 K**。

> ⚠️ **别误解成"省单次点积的 FLOPs"**（换结合顺序不会凭空省算力，取决于维度）。它真正省的是：

| | 不吸收(只存c_KV,用时解压) | 矩阵吸收 |
|---|---|---|
| 每步升维 W_UK 作用在 | **全部 S 个历史缓存**上(每步重来) | **只 1 个当前 query** 上 |
| 缓存大小 | 小(c_KV) | 小(c_KV) |
| 完整 K/V | 每步摊开(占显存) | 从不摊开 |

- **核心红利 = 显存/访存**：让"缓存只存小 c_KV"和"不必每步对整段历史重复解压"两个好处**同时拿到**。
- 代价：吸收后 query 侧点积维度变成 `d_c`(如512) 而非 `head_dim`(128)，**点积那步 FLOPs 甚至略增**——用"算力略增"换"显存大降"。
- 正因 RoPE 段是随位置变的矩阵、**无法**被提前合并，才需要第 3 点的解耦。

> 一句话：矩阵吸收 = 把 W_UK 从"作用在 S 个历史缓存上"挪到"作用在 1 个 query 上"，从而不必每步解压整个 KV 缓存、缓存也只需存小 c_KV。**是显存/访存优化，不是单次点积省 FLOPs。**

#### 5. 四者换个对比轴才公平

| 方法 | 缓存的是什么 | 对比轴 | KV Cache/每token |
|------|-------------|--------|------------------|
| MHA | 每头真实 K/V | 头数 = h | 最大(`2·h·head_dim`, 如 2×128×128=32768) |
| GQA | 少数头 K/V | 头数 = g | 中 |
| MQA | 1 个头 K/V | 头数 = 1 | 小 |
| **MLA** | **压缩潜向量 c_KV(+RoPE段)** | **低秩压缩** | **最小**(`d_c+d_R`, 如 512+64=576)，质量接近/超 MHA |

> 面试一句话：**MHA/MQA/GQA 沿"头数"轴滑动（存真实 K/V）；MLA 跳到"压缩"轴——下投影直接把 hidden 压成潜向量 c_KV 存缓存、用时上投影还原(且可矩阵吸收)，再靠解耦 RoPE 处理位置**。所以进不了"改头数"的形状表，得单独讲。

#### 6. 扩展：KV Cache 压缩方法全景（可叠加）

MLA 只是其中"低秩"这一种。整个"减小 KV Cache"领域主流四类：

| 方法 | 思路 | 代表 |
|------|------|------|
| **头共享** | 减少 K/V 头数，多 Q 头共享 | MQA、GQA |
| **低秩压缩** | K/V 投影到低维潜向量存，用时升维 | **MLA** |
| **量化** | K/V 用低位宽(4/8bit)存，省每个数的字节 | KV Cache 量化(本项目端侧也改写了 KV) |
| **稀疏/淘汰** | 只保留重要/最近的 token，丢弃其余 | 滑动窗口、StreamingLLM、H2O |

> 这四类**可组合**（如 GQA + KV 量化）。头共享和低秩是"改结构"层面的不同选择；量化、淘汰是另外两个正交维度。

## 四、按效率优化分（解决 O(n²) 痛点）

标准注意力的瓶颈：序列长 n，`QK^T` 是 `n×n`，**算力和显存都是 O(n²)**。优化分两条路：

### A. 改"算法/数学"（近似，少算一些）
| 类型 | 思路 | 复杂度 | 代表 |
|------|------|--------|------|
| **稀疏注意力** Sparse | 只算部分位置对(固定/块状模式) | O(n√n)等 | Sparse Transformer |
| **滑动窗口** Sliding Window | 只看最近 W 个 | O(n·W) | Longformer、Mistral |
| **线性注意力** Linear | 用核函数去掉 softmax，改变结合律 | **O(n)** | Performer、Linformer、Linear Transformer |

### B. 改"工程/IO"（数学不变，结果精确，只是算得快）
| 类型 | 思路 | 关键点 |
|------|------|--------|
| **FlashAttention** | 分块(tiling)+在 SRAM 里融合计算+重算省显存 | **精确**注意力，不近似；省的是显存读写(IO)，不是浮点运算量 |

> ⭐面试陷阱：**FlashAttention 不是一种"新注意力算法"，结果和标准注意力完全一致**，它是 IO 感知的高效实现。别和"稀疏/线性"这类近似法混为一谈。

## 五、按打分函数分（相关性怎么算）

| 类型 | 公式 | 出处 |
|------|------|------|
| **加性 / 拼接** Additive | $score = v^\top \tanh(W[q;k])$ | Bahdanau 2014 |
| **点积** Dot-Product | $score = q \cdot k$ | Luong 2015 |
| **缩放点积** Scaled Dot-Product | $score = \dfrac{q \cdot k}{\sqrt{d}}$ | Transformer 2017 |

> Transformer 用**缩放点积**：点积比加性快(纯矩阵乘)，除 $\sqrt{d}$ 防 softmax 饱和(为什么除见 [附录A 2.3](./02-附录A-Attention注意力机制.md))。

## 六、按工程实现分（HuggingFace 里的 `attn_implementation`）

| 取值 | 是什么 | 特点 |
|------|--------|------|
| `eager` | 纯 PyTorch 逐步实现 | 最慢但最透明、易改写。**本项目 QcAttention 走这条**(便于插量化算子) |
| `sdpa` | 调 PyTorch `scaled_dot_product_attention` | 自动选最优内核，较快 |
| `flash_attention_2` | 调 FlashAttention-2 内核 | 最快、省显存，需硬件支持 |

> 三者**数学结果一致**，区别只在速度/显存/可改写性。本项目选 `eager` 是因为要往里塞量化专用算子(`Add()`、Conv 投影等)。

## 八、面试速答模板

- **Self vs Cross**：QKV 同源是自注意力；Q 与 K/V 异源是交叉注意力。
- **为什么要因果掩码**：自回归生成防止偷看未来，保证训练/推理一致。
- **MHA/MQA/GQA 区别**：Q 头都是 h；KV 头分别是 h / 1 / g。目的是减小 KV Cache 和访存。Qwen2 用 GQA。
- **FlashAttention 是什么**：IO 感知的**精确**注意力实现(分块+重算)，省显存读写，不改数学、不是近似。
- **怎么处理长序列**：滑动窗口 / 稀疏 / 线性注意力(近似) 或 FlashAttention(精确提速)。
- **缩放点积为什么除 √d**：防止点积过大导致 softmax 饱和、梯度消失。

## 九、记忆锚点

- **六个切分维度**：来源 / 可见范围 / 多头结构 / 效率 / 打分 / 实现。
- **最高频两块**：② 因果vs双向、③ MHA/MQA/GQA/MLA。
- **MHA/MQA/GQA 形状**：Q 永远满头；K/V 头数 = h / 1 / g。头数 = 投影输出维度 ÷ head_dim。
- **头数由谁定**：MHA 由 config/reshape 切（K/V 输出=hidden 给够）；MQA/GQA 由 k/v_proj 输出维度砍小卡死。
- **权重形状**：Linear 权重 `[out,in]`，in=hidden、out=头数×head_dim。矩阵乘压到 out 维，再 reshape 切成(头数,head_dim)。MQA的K：`[128,2048]`→输出128→reshape (1,128)。
- **K/V 补齐**：MQA 靠广播、GQA 靠 `repeat_kv`；省的是存储/访存，不是计算量。
- **GQA 分组**：Q 头连续平均分 g 组(g=KV头数)，每组共享 1 份 KV；`num_heads` **必须整除** `num_kv_heads`(否则报错)。MHA/MQA 是 g=头数/g=1 两端。
- **MLA 本质**：下投影把 hidden 直接压成潜向量 c_KV 存缓存(K/V共享一份)，用时上投影还原；完整K/V从不存。低秩分解 `W_K=W_UK×W_DKV`。
- **MLA 细节**：Q 不缓存(可当普通投影)；解耦 RoPE 额外存一小段(64)，`head_dim=d_h+d_R`；矩阵吸收把 W_UK 挪到 query 侧、免每步解压历史(是显存优化，非省单次点积FLOPs)。
- **RoPE 存哪**：MHA/MQA/GQA 的 K 带 RoPE(先转后存)、V 不带；MLA 存共享的 k_R(带RoPE) + c_KV(不带)。k_R 跨头共享但跨位置不同 → RoPE 仍有效，头差异靠内容段。
- **KV压缩四类**：头共享(MQA/GQA)、低秩(MLA)、量化、稀疏淘汰，可叠加。
- **易错点**：FlashAttention 是"精确+快"，不是"近似"；它属于"实现"不属于"算法变体"。
- **本项目落点**：自注意力 + 因果 + GQA + 缩放点积 + RoPE + eager 实现。
