# 03 · 附录A · 模型权重文件格式

> **关联**：[03-模型与Tokenizer加载与config覆盖](./03-模型与Tokenizer加载与config覆盖.md) 里 `from_pretrained` 加载的就是 `.safetensors`；本项目量化后会导出 `.onnx + .encodings`（见 07 ONNX 导出）。
> **一句话本质**：权重文件就是"把模型的一堆张量(+元数据)存到磁盘"的方式；不同格式在**安全性、加载速度、是否自带量化、面向哪种部署**上各有取舍。

> **本篇为背景概念篇，轻量两段式**：**① 介绍（为什么有这么多格式）→ ② 原理（按生态分类 + 分片机制 + 本项目链路）**。「官方/改造做法」不涉及。

---

## 一、介绍：为什么权重格式有这么多

一个模型训练完，本质就是**一大堆命名张量**（`model.layers.0.self_attn.q_proj.weight` 之类）。把它们落盘时，不同场景有不同诉求，于是演化出多种格式：

- **安全**：老的 pickle 格式能在加载时执行任意代码 → 催生 `.safetensors`。
- **速度**：想 mmap 零拷贝、按需只读某个张量 → `.safetensors`。
- **自带量化 + 单文件本地跑**：CPU/手机本地推理 → `.gguf`。
- **跨框架 / 部署**：脱离 PyTorch 去别的运行时 → `.onnx`、`.dlc`、TensorRT engine。

所以"格式"不是越多越乱，而是**每种对应一类使用场景**。

## 二、原理：按生态分类

### 2.1 PyTorch 生态（训练 / HuggingFace 分发，最常见）

| 格式 | 后缀 | 本质 | 特点 |
|---|---|---|---|
| **Pickle 权重** | `.bin` `.pt` `.pth` | Python `pickle` 序列化的 `state_dict` | 老标准。**能执行任意代码 → 安全风险**；加载慢、不能部分读取 |
| **SafeTensors** | `.safetensors` | 纯张量数据 + JSON 头（记名字/形状/dtype/偏移） | HF 现主推。**安全**（纯数据无代码）、**mmap 零拷贝加载快**、可只读单个张量；详见 [03-附录B](./03-附录B-mmap与数据搬运路径.md) |

`.safetensors` 就是为取代 `.bin` 而生，解决 pickle 的安全与速度问题；现在 HF 上模型基本默认发它。

### 2.2 大文件分片（sharding）

大模型一个文件装不下，会拆成多片 + 一个索引：

```
model-00001-of-00004.safetensors
model-00002-of-00004.safetensors
...
model.safetensors.index.json   ← "哪个张量在哪一片"的目录表（不是权重）
```

本项目的 Qwen2.5-VL-3B 就是这种多片 safetensors 形式。

### 2.3 llama.cpp / 端侧 CPU 生态

| 格式 | 后缀 | 说明 |
|---|---|---|
| **GGUF** | `.gguf` | llama.cpp 现行格式，权重 + 元数据 + **量化**打包进一个文件，支持 Q4_K_M 等多种量化 |
| GGML | `.ggml` `.bin` | GGUF 前身，已淘汰 |

GGUF 最大特点是**自带量化、单文件即可在 CPU/手机跑**，是本地推理（Ollama、LM Studio）的主流。

### 2.4 跨框架 / 部署格式

| 格式 | 后缀 | 说明 |
|---|---|---|
| **ONNX** | `.onnx` | 跨框架中间表示，含**结构图 + 权重**；权重超 2GB 时外挂到 `.onnx.data` |
| TensorRT engine | `.engine` `.plan` | NVIDIA GPU 编译后的推理引擎 |
| OpenVINO IR | `.xml` + `.bin` | Intel 部署格式 |

### 2.5 高通端侧（本项目相关）⭐

| 格式 | 后缀 | 说明 |
|---|---|---|
| **ONNX** | `.onnx` | 本项目量化后**导出的中间产物** |
| **AIMET encodings** | `.encodings` | AIMET 量化产生的**量化参数**（scale/offset），配合 ONNX 用 |
| QNN 模型库 | `.cpp`/`.bin`/`.so` | QNN 把模型转成的中间形态 |
| **DLC** | `.dlc` | 高通 SNPE 部署格式 |
| QNN context binary | `.bin` | 编译到具体 HTP 后的最终端侧产物 |

### 2.6 其他框架（了解即可）

| 生态 | 格式 |
|---|---|
| TensorFlow | SavedModel（目录）、`.ckpt`、`.h5`（Keras）|
| JAX/Flax | `.msgpack`（orbax checkpoint）|
| Apple MLX | `.safetensors`（复用）/ `.npz` |
| NumPy | `.npy`（单数组）、`.npz`（多数组打包）|

### 2.7 本项目权重流转链路

```
.safetensors (官方权重, 多片 + index.json)
   │ from_pretrained 加载（见 03 正文 4.4）
   ▼
改造 + 量化（QuantSim / SeqMSE）
   │ 导出
   ▼
.onnx  +  .encodings（结构图 + 量化参数）
   │ QNN / QAIRT 工具编译
   ▼
.dlc / QNN context .bin（端侧最终产物）
```

## 三、记忆锚点

- **训练 / HF 分发**：`.safetensors`（新，安全+快）取代 `.bin/.pt`（旧，pickle 有风险）；大模型分片 + `index.json`。
- **本地 CPU 推理**：`.gguf`（自带量化、单文件）。
- **跨框架 / 部署**：`.onnx`。
- **高通端侧（本项目）**：`.onnx + .encodings` → `.dlc` / QNN context `.bin`。
- **一句话**：格式差异 = 安全 / 速度 / 自带量化 / 面向哪种部署 的不同取舍。
