# E3-03 · 设备端启动与日志分层

> **在整个流程中的位置**：Embedding、运行库、模型与配置全部准备完成 → **在设备上启动 Genie 并检查运行日志**。
>
> **一句话本质**：最后一步不是继续转换模型，而是让动态链接器、FastRPC、QNN HTP、Context Binary 和 Genie 生成循环依次启动。

## 一、启动前先检查什么

设备目录至少应能解析到：

```text
genie-t2t-run
libGenie.so
QNN HTP/System/Extension/Stub 库
对应架构的 HTP Skeleton/.cat
qwen25vl3B_os.json
htp_backend_ext_config.json
tokenizer.json
models/*.serialized.bin
embedding_weights_151936x2048.raw
inputs_embeds.bin
```

其中主配置使用相对路径，因此执行目录和文件布局必须与配置一致。

## 二、设置三个搜索路径

官方较新的 Android QAIRT 布局通常使用：

```bash
export QAIRT_HOME=/path/to/qairt
export PATH=${QAIRT_HOME}/bin/aarch64-android:${PATH}
export LD_LIBRARY_PATH=${QAIRT_HOME}/lib/aarch64-android:${LD_LIBRARY_PATH}
export ADSP_LIBRARY_PATH=${QAIRT_HOME}/lib/hexagon-v81/unsigned
```

它们分别负责：

| 变量 | 查找内容 |
|---|---|
| `PATH` | `genie-t2t-run` 可执行程序；使用 `./genie-t2t-run` 时可不依赖它 |
| `LD_LIBRARY_PATH` | ARM CPU 侧的 Genie、QNN、Stub 等 `.so` |
| `ADSP_LIBRARY_PATH` | DSP/HTP 侧的 Skeleton、`.cat` 等文件 |

仓库 README 还提到 `CDSP_LIBRARY_PATH`；是否需要应以目标平台和对应 QAIRT 版本为准，不能默认所有设备都必须同时设置。

## 三、先检查当前 CLI 支持什么

本仓库使用：

```bash
./genie-t2t-run \
  -c qwen25vl3B_os.json \
  -e inputs_embeds.bin \
  -t embedding_weights_151936x2048.raw
```

但较新的官方 Genie CLI 主要展示 `-p` 或 `--prompt_file`。所以实操时第一条命令应是：

```bash
./genie-t2t-run --help
```

只有 `--help` 明确支持 `-e/-t`，才能使用本项目命令。否则说明项目样例与设备上的 Genie 版本不是同一套接口，不能直接照抄。

## 四、一条命令启动后发生什么

```text
1. Android 动态链接器加载 libGenie.so 和 QNN CPU 侧库
2. Genie 解析 qwen25vl3B_os.json
3. 加载 tokenizer.json 和 HTP 扩展配置
4. QNN HTP 初始化设备与 FastRPC
5. DSP 侧加载匹配架构的 Skeleton
6. QNN System 恢复全部 Context Binary
7. Genie 读取 Embedding Table 和 inputs_embeds.bin
8. AR128 图执行 prefill
9. AR1 图逐 token 执行 decode
10. Tokenizer 把输出 token ID 还原为文字
```

只有第 10 步发生，才算真正完成一次端侧生成。

## 五、怎样通过错误判断卡在哪一层

| 日志或现象 | 更可能的问题层 |
|---|---|
| `not found`、`cannot open shared object` | `LD_LIBRARY_PATH`、CPU ABI 或缺少 `.so` |
| FastRPC、Skel、PD session 错误 | `ADSP_LIBRARY_PATH`、DSP 架构、signed/unsigned 权限 |
| `incompatible binaries`、Context create/restore 失败 | Context Binary、QAIRT 版本、SoC/HTP 不匹配 |
| JSON parse、Tokenizer load 失败 | 配置格式或相对文件路径 |
| 输入字节数、shape、datatype 错误 | `inputs_embeds.bin` 或 Embedding Table 的 dtype/维度 |
| 能生成但文本异常 | Tokenizer、特殊 token、RoPE/MRoPE、模型/配置不一致 |

排错时应找第一条真实错误，不能只看最后的“创建对话失败”。

## 六、什么才算运行成功

至少要观察到：

```text
Genie 动态库版本被打印
→ QNN HTP 后端初始化成功
→ 所有 Context Binary 加载成功
→ prefill 完成
→ decode 持续产生 token
→ token 被还原成可读文本
```

如果还要验收精度和性能，则继续记录：

- 输出是否与参考模型语义一致；
- Time To First Token；
- Decode tokens/s；
- 峰值内存；
- 是否出现 HTP fallback 或异常警告。

## 七、当前仓库的实际状态

当前工作区没有设备连接信息、QAIRT 设备端运行库和 Context Binary，且配置仍存在 `1_of_1`/`6_of_6`、`v79`/`v81` 不一致。因此这里只能学习启动顺序和日志分层，尚未实际执行或验收。
