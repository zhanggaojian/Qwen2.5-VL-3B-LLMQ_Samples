# 07-附录F · 量化方法总览与选型

> **所属主篇**：[07 · 量化主流程](./07-量化主流程-QuantSim到Encoding.md)
>
> **本文定位**：建立量化方法的全景地图，回答“量化什么、何时量化、怎样确定 Encoding、按什么粒度量化，以及应该怎样选方法”。
>
> **一句话本质**：一个完整量化方案不是单个算法名，而是“量化对象 + PTQ/QAT + 静态/动态 + 位宽与数值格式 + 量化粒度 + 范围标定／误差控制策略”的组合。

## 一、为什么需要单独整理量化方法

量化领域经常同时出现下面这些词：

```text
W4A16、INT8、PTQ、QAT、静态量化、动态量化、
Per-Channel、SeqMSE、GPTQ、AWQ、SmoothQuant……
```

它们属于基本正交、但又受到具体实现和硬件约束的不同维度，不能直接放在一条线上比较。例如：

- `W4A16` 描述的是**对象和位宽**；
- PTQ、QAT 描述的是**介入模型的阶段**；
- 静态、动态描述的是 **Encoding 的确定时机**；
- Per-Tensor、Per-Channel、Per-Group 描述的是**共享 Encoding 的粒度**；
- SeqMSE、GPTQ、AWQ 描述的是**降低量化误差的算法**。

因此，理解一个量化方案时，至少要分别回答以下问题：

| 维度 | 要回答的问题 | 示例 |
|---|---|---|
| 量化对象 | 量化哪些张量 | Weight、Activation、KV Cache |
| 介入阶段 | 训练后处理还是训练中适应 | PTQ、QAT |
| Encoding 时机 | 离线固定还是运行时计算 | 静态、动态 |
| 数值规格 | 使用什么格式和位宽 | INT4、INT8、FP8、W4A16 |
| 量化粒度 | 哪些元素共享一组 Encoding | Per-Tensor、Per-Channel、Per-Group、Per-Token |
| 范围标定／误差控制策略 | 怎样选择范围、舍入、变换或补偿误差 | Min-Max、SeqMSE、GPTQ、AWQ 等 |

一套方案可以同时属于多个分类。例如，本项目可以概括为：

```text
PTQ
+ 静态 Encoding
+ 默认 W4A16
+ QuantSim 均匀仿射量化
+ SeqMSE 优化部分低比特 Weight Encoding
+ compute_encodings 标定 Activation Encoding
+ 局部混合精度与 KV Cache 相关规则
```

## 二、所有方法共享的量化地基

### 2.1 量化的基本动作

以常见的均匀仿射整数形式为例，浮点数 `x` 被映射到有限整数范围：

\[
q=clip\left(round\left(\frac{x}{scale}\right)+z\right)
\]

需要模拟浮点计算时，再反量化：

\[
\hat{x}=(q-z)\times scale
\]

其中：

- `bitwidth` 决定可用整数等级数量；
- `scale` 决定相邻量化等级的间距；
- `z` 表示通用公式中的 zero-point，决定零点映射；
- `min/max` 决定覆盖范围和裁剪边界。

AIMET 不同 Encoding 版本中还可能使用名为 `offset` 的字段，其符号约定不一定与这里的 `z` 相同，不能脱离具体 Encoding 格式直接代入上述公式。

这些信息统称为 Quantization Encoding，详见 [07-附录B · Encoding 量化参数基础](./07-附录B-Encoding量化参数基础.md)。

### 2.2 不同方法真正争论的是什么

很多方法最终使用的仍然是相同的 INT4/INT8 量化公式，真正的区别通常是：

```text
范围怎么选？
异常值要不要裁剪？
每个权重向上还是向下舍入？
哪些通道更重要？
已经产生的误差怎样补偿？
是否允许通过训练调整模型？
```

因此，SeqMSE 不是一种新的“INT4 格式”，而是一种选择 Weight Encoding 的优化方法；GPTQ、AWQ 等也主要是在“怎样获得更好的低比特模型”这一层面工作。

### 2.3 QuantSim 里的量化与真实部署

QuantSim 通常使用 QDQ 模拟量化：

```text
浮点张量 x
   ↓ Quantize
整数网格值 q
   ↓ Dequantize
受量化网格限制的浮点张量 x_hat
```

此时张量的数据类型可能仍显示为浮点，但有效数值已经受到 INT4/INT8 网格限制。导出并经过后端编译后，权重才可能被真正打包为低比特整数，算子也可能由 NPU/HTP 整数内核执行。

QuantSim、Quantizer 和 QDQ 的对象关系详见 [07-附录A · QuantSim 模型骨架与 QDQ](./07-附录A-QuantSim模型骨架与QDQ.md)。

## 三、维度一：量化对象

### 3.1 Weight 量化

Weight 是模型文件中已经存在的固定参数。普通 Min-Max 权重量化可以直接扫描权重范围，不需要先跑模型前向。

主要收益：

- 减少模型文件和运行时权重内存；
- 降低权重读取带宽；
- 在后端支持时使用低比特矩阵乘或卷积内核。

常见规格包括 W8、W4、W3，以及 Weight-Only 的 W4A16。

### 3.2 Activation 量化

Activation 是前向计算过程中产生的中间张量，分布取决于真实输入。静态 Activation 量化通常需要运行代表性校准数据，统计范围后固定 Encoding。

主要收益：

- 减少中间张量内存；
- 降低算子之间的数据搬运；
- 允许使用整数矩阵乘等低精度计算。

Activation 往往比 Weight 更难量化，因为它会随样本、Token 和层发生变化，还可能包含明显异常值。

### 3.3 KV Cache 量化

KV Cache 是自回归推理中保存的 K、V 张量。本质上它是一种跨 Token 保存的特殊 Activation 或模型状态，但由于长上下文下占用显存大、读写频繁，通常单独讨论。

主要收益：

- 降低长上下文 KV Cache 容量；
- 减少 Decode 阶段 Cache 读写带宽；
- 提高有限内存下可支持的上下文长度。

KV Cache 可以使用离线标定后固定的 Encoding，也可以在运行时按 Token、Head、Channel 或 Group 动态计算量化参数。

### 3.4 三类对象的关系

| 对象 | 模型加载时是否已经存在 | 确定静态 Encoding 通常是否需要前向 | 常见难点 |
|---|---:|---:|---|
| Weight | 是 | 普通范围统计不需要；SeqMSE 等优化方法需要 | 低比特舍入、通道差异、异常值 |
| Activation | 否 | 需要 | 输入相关、分布变化、异常值 |
| KV Cache | 否 | 需要有代表性的 Prefill/Decode 数据 | 跨 Token 变化、长上下文、读写带宽 |

## 四、维度二：PTQ 与 QAT

### 4.1 PTQ：训练后量化

PTQ（Post-Training Quantization）在预训练模型完成后进行量化，不重新执行原模型的完整训练流程。

```text
已有浮点模型
    ↓
范围统计、校准或局部优化
    ↓
量化模型
```

PTQ 的优势是成本较低、流程较快，适合已有模型部署。需要注意：PTQ 不等于“完全不使用数据”或“完全不做优化”。

- 普通 Weight Min-Max 可以不使用校准数据；
- Activation 标定需要代表性数据；
- SeqMSE、GPTQ、AWQ 等需要少量校准样本；
- AdaRound、OmniQuant 等 PTQ 方法内部可以优化辅助变量，但并没有重新完成原模型训练。

### 4.2 QAT：量化感知训练

QAT（Quantization-Aware Training）在训练或微调阶段插入模拟量化误差：

```text
浮点模型
   ↓ 插入 Fake Quant / QDQ
带量化噪声继续训练或微调
   ↓
模型权重和／或可学习量化参数主动适应量化误差
```

QAT 通常具有更高的极低位精度潜力，但需要训练资源、数据、优化器状态和更复杂的训练流程。

### 4.3 PTQ 与 QAT 对比

| 对比项 | PTQ | QAT |
|---|---|---|
| 介入时间 | 模型训练完成后 | 训练或微调阶段 |
| 数据需求 | 无数据到少量校准数据 | 通常需要训练或微调数据 |
| 是否反向传播 | 基础 PTQ 不需要；部分优化型 PTQ 会优化辅助变量 | 需要 |
| 计算成本 | 较低 | 较高 |
| 极低位精度潜力 | 取决于算法和模型 | 通常更高 |
| 工程复杂度 | 较低 | 较高 |

## 五、维度三：静态量化与动态量化

最核心区别是 Encoding 的确定时机：

```text
静态量化：离线统计／校准／学习 → 推理前固定 Encoding
动态量化：当前运行张量         → 推理时实时计算 Encoding
```

| 对比项 | 静态量化 | 动态量化 |
|---|---|---|
| Encoding 计算时间 | 部署前 | 推理时 |
| 是否需要离线校准 | Activation/KV 通常需要 | 通常不依赖固定离线范围 |
| 对当前数据分布的适应能力 | 较弱 | 较强 |
| 运行时统计开销 | 较小 | 较大 |
| 后端部署 | 通常更容易固定编译 | 需要后端支持动态尺度和量化 |
| 常见对象 | Weight、Activation、KV Cache | Activation、KV Cache |

需要记住两个边界：

1. Activation 或 KV Cache 在运行时动态产生，不代表它采用了动态量化；只要一直使用固定 Encoding，仍然属于静态量化。
2. SeqMSE 虽然要跑前向，但前向发生在离线搜索阶段，搜索结束后 Weight Encoding 被固定，所以仍然属于静态 PTQ。

静态和动态也可以组合，例如：

```text
Weight：静态 INT4
Activation：静态 INT8
KV Cache：动态 INT8
```

## 六、维度四：位宽、数值格式与量化粒度

### 6.1 位宽写法

常见写法：

| 写法 | 含义 |
|---|---|
| W8A8 | Weight 8 bit，Activation 8 bit |
| W4A16 | Weight 4 bit，Activation 16 bit |
| W4A8 | Weight 4 bit，Activation 8 bit |
| KV8 | KV Cache 8 bit |

W4A16 只描述默认对象位宽，不说明采用 PTQ 还是 QAT，也不说明使用 SeqMSE、GPTQ 还是其他误差控制策略。

还要注意语境差异：LLM 论文中的 W4A16 经常被用作“INT4 Weight + FP16 Activation”的 Weight-Only 简写；本工程的 `default_output_bw: 16` 则是为配置中启用的 Activation Quantizer 设置默认 16 bit。Quantizer 是否放置、启用或共享还受 HTP 配置和局部规则影响，不能直接把它理解成全图 Activation 都是量化 A16，也不能理解成完全不量化的 FP16 Activation。

如果不同层、不同参数或不同 Activation 使用不同位宽，就属于混合精度配置。混合精度描述的是**位宽分配策略**，也不是 SeqMSE、GPTQ 这一类误差控制策略。

### 6.2 数值格式

- INT8、INT4：整数网格，常配合 `scale/zero-point`；AIMET legacy Encoding 也可能记录版本相关的 `offset`；
- FP8、FP4：低位浮点格式，具有指数和尾数；
- NF4 等非均匀格式：量化等级不是普通均匀整数间隔。

能否真正加速不仅取决于位宽，还取决于目标硬件、编译器、算子内核和数据布局是否支持该格式。

### 6.3 对称与非对称量化

- 对称量化通常让范围围绕 0 对称，零点结构简单；
- 非对称量化允许正负范围不同，可能更充分利用量化等级；
- 权重常见对称量化，Activation 是否对称需要结合分布和后端约束。

这里的对称量化开关，不要与 SeqMSE 的 `inp_symmetry` 输入配对策略混淆。

### 6.4 量化粒度

| 粒度 | Encoding 共享范围 | 特点 |
|---|---|---|
| Per-Tensor | 整个张量一组 | 元数据少、实现简单，容易被异常通道拖累 |
| Per-Channel | 每个输出通道一组 | Weight 精度通常更好，后端需支持 |
| Per-Group | 每组若干权重一组 | LLM W4 常见，在精度和元数据之间折中 |
| Per-Token | 每个 Token 一组 | 适应 Activation/KV 的 Token 间变化，运行时开销更高 |
| Per-Head | 每个 Attention Head 一组 | 可适应不同 Head 的 K/V 分布 |

粒度越细通常越能适应局部分布，但会增加 scale/offset 元数据、计算和后端实现复杂度。

## 七、基础范围选择方法

这些方法主要回答：量化的 `min/max` 或裁剪阈值怎样确定？

| 方法 | 核心规则 | 优点 | 主要风险 |
|---|---|---|---|
| Min-Max | 覆盖观察到的最大值和最小值 | 简单、快速 | 少量异常值会拉大量化范围 |
| Percentile | 裁掉超过指定分位点的极少数值 | 减弱异常值影响 | 百分位选择不合适会过度裁剪 |
| Tensor MSE | 搜索使 `x` 与 `QDQ(x)` 重构误差较小的范围 | 直接考虑量化误差 | 未考虑误差经过真实层后的影响 |
| KL/Entropy | 选择尽量保持原分布信息的范围 | 常用于 Activation 校准 | 结果依赖统计直方图和实现细节 |

范围选择和舍入规则也是两个步骤。确定 Encoding 后，普通基线通常采用 Round-to-Nearest（RTN，舍入到最近量化格点）；AdaRound 则进一步优化每个 Weight 的舍入方向。

本工程配置中的：

```yaml
quant_scheme: post_training_tf
```

是 AIMET 的 legacy TF-style Min-Max Encoding 方案；这里的 `tf` 表示这种历史命名的“使用观测到的 Tensor 最小值和最大值”规则，不代表调用 TensorFlow，也不是 `tf_enhanced` 或 Tensor MSE 搜索。它先提供普通量化基础，后续再用 SeqMSE 优化满足条件的 Weight Encoding。

## 八、SeqMSE 与普通量化的区别

### 8.1 一句话区别

本节的“普通量化”特指当前项目的基础 **Min-Max 权重量化**（通常配合 RTN 舍入）。因为 SeqMSE 优化的是 Weight Encoding，所以表格比较的不是普通 Activation Calibration；后者仍然需要真实数据前向。

```text
普通 Weight Min-Max：根据权重自身范围选 Encoding
SeqMSE：根据真实层输入下的输出误差选 Weight Encoding
```

| 对比项 | 普通 Min-Max 权重量化 | SeqMSE |
|---|---|---|
| 在完整流程中的角色 | 建立基础 Weight Encoding | 在普通 QuantSim 基础上优化部分低位宽 Weight Encoding |
| 判断依据 | Weight 的 min/max | 参考输出与候选量化输出的误差；当前为 `x_q·W` 对比 `x_q·Q(W)` |
| 是否需要数据 | 通常不需要 | 需要代表性校准数据 |
| 是否跑前向 | 通常不需要 | 需要采集逐层输入 |
| 搜索过程 | 通常直接计算一组范围 | 每层尝试多组候选 Encoding |
| 优化目标 | 覆盖权重范围 | 最小化层输出重构误差 |
| 覆盖范围 | 按配置启用且允许计算的 Parameter Quantizer | 仅优化 AIMET 支持且满足条件的低位宽层 |
| 最终产物 | Weight Encoding | 搜索并冻结的 Weight Encoding |
| 计算成本 | 低 | 较高 |

二者并不是两种互不相干的 INT4 格式。它们都属于静态 PTQ，都保留原始浮点 Weight，最终都得到供 QDQ 和导出使用的 Weight Encoding。SeqMSE 不改变位宽、量化公式或文件格式，只改变“怎样选出更合适的 Encoding”。

还要避免一句常见的过度概括：**“普通量化不需要前向”只适用于普通 Weight Min-Max**。普通静态 Activation／KV Calibration 仍需要前向，因为这些张量只有模型运行时才会产生。

### 8.2 为什么输出 MSE 可能比权重 MSE 更合理

对于线性层，可以先一般化地写成：

\[
y=xW
\]

量化后：

\[
\hat{y}=xQ(W)
\]

不同权重位置对输出的影响，还取决于真实输入 `x`。某个权重数值误差较大，但对应输入长期接近 0，它对最终输出的影响可能很小；反过来，一个经常被大激活使用的权重，即使量化误差不大，也可能更重要。

SeqMSE 因此比较层输出误差，而不是只比较 `W` 和 `Q(W)` 的数值差异。

当前项目使用 `inp_symmetry=symqt`，两边共享 QuantSim 前序路径产生的层输入，所以更精确的写法是：

\[
y_{ref}=x_qW,\qquad y_q=x_qQ(W)
\]

### 8.3 一个概念例子

假设某层大部分权重位于 `[-0.3, 0.3]`，但少数异常值达到 `[-1.2, 1.2]`。4 bit 只有 16 个量化等级：

```text
候选 1：[-1.2, 1.2] → 不裁异常值，但量化步长较粗
候选 2：[-0.9, 0.9] → 轻度裁剪，步长更细
候选 3：[-0.6, 0.6] → 更多裁剪，主体权重表示更精细
```

普通 Min-Max 通常直接采用候选 1。SeqMSE 会让每个候选参与真实层计算，并选择输出 MSE 最小的范围；它可能选择候选 2 或候选 3。

### 8.4 SeqMSE 不是完整量化流程的替代品

SeqMSE 只优化受支持层的 Parameter Encoding。它仍需要：

- QuantSim 创建 Quantizer 和 QDQ 骨架；
- 量化配置指定 bitwidth、对称性和粒度；
- `compute_encodings()` 标定 Activation，并从参数张量计算或重算允许覆盖的 Parameter Encoding；
- PPL 或任务指标验证整体精度；
- Export 和后端编译完成真实部署。

SeqMSE 的代码、候选搜索和 `inp_symmetry` 详见 [07-附录D · SeqMSE 权重量化优化](./07-附录D-SeqMSE权重量化优化.md)。

## 九、常见优化型 PTQ 方法

### 9.1 总体对比

| 方法 | 主要优化对象 | 核心思想 | 是否需要校准数据 | 典型定位 |
|---|---|---|---:|---|
| SeqMSE | Weight Encoding | 逐层搜索候选范围，使层输出重构误差更小 | 是 | AIMET 低比特 Weight Encoding 优化 |
| AdaRound | Weight 舍入方向 | 不固定使用最近舍入，学习每个权重向上还是向下取整 | 是 | 通用低比特 PTQ |
| GPTQ | Weight 块及误差补偿 | 利用近似二阶信息逐块量化，并补偿已量化权重造成的误差 | 是 | LLM Weight-Only W4/W3 |
| AWQ | 重要 Weight 通道 | 根据 Activation 识别显著通道，通过等价缩放保护重要权重 | 是 | LLM/VLM Weight-Only W4 |
| SmoothQuant | Activation 异常值 | 通过等价缩放把部分 Activation 量化难度迁移到 Weight | 是 | LLM W8A8 |
| OmniQuant | 裁剪与等价变换参数 | 用可微分的块级重构学习裁剪和变换 | 是 | LLM 低比特 Weight-Only 或 W+A |

这些方法不一定互斥。例如，SmoothQuant 可以先处理 Activation 异常值，再配合其他 Weight 量化方法；但能否组合以及组合顺序必须由具体工具链和后端验证。

QAT 属于训练阶段范式，不是 PTQ 方法，因此没有放入上表；它与 PTQ 的完整对比见第四节。

### 9.2 AdaRound

普通最近舍入只看某个权重离哪个量化格点最近：

```text
0.26 → 0.3
```

AdaRound 会结合少量数据和局部重构损失，判断选择 `0.2` 还是 `0.3` 对模型更有利。它主要优化**舍入决策**，而 SeqMSE 主要搜索**Encoding 范围**。

### 9.3 GPTQ

GPTQ 面向大规模 Transformer Weight-Only 量化，逐块处理权重，并利用近似二阶信息估计量化某个权重对输出的影响，再调整尚未量化的权重以补偿误差。

它常见于 GPU 上的 W4A16/W3A16 模型生态，但是否能直接用于特定 NPU/HTP 部署，取决于导出格式和后端内核支持。

### 9.4 AWQ

AWQ 的核心观察是：不同权重通道的重要程度不同，而 Activation 分布可以帮助识别重要通道。它通过等价缩放保护显著通道，避免简单 Weight-Only 量化破坏关键输出。

AWQ 主要面向 LLM/VLM Weight-Only 低比特量化，不等同于 Activation 量化。

### 9.5 SmoothQuant

LLM 的 Activation 往往包含难以量化的异常值。SmoothQuant 使用数学等价的缩放变换：

```text
减小 Activation 通道的异常范围
          ↓
把相应尺度吸收到 Weight 中
```

这样把一部分量化难度从 Activation 转移到更容易离线处理的 Weight，典型目标是 W8A8。

### 9.6 OmniQuant

OmniQuant 在少量校准数据上，以块级输出重构为目标，学习 Weight Clipping 和等价变换参数。它仍属于 PTQ，但内部包含可微分优化，所以“PTQ 一定没有梯度”并不准确。

### 9.7 Cross-Layer Equalization 等辅助方法

CLE（Cross-Layer Equalization）通过跨相邻层缩放权重范围，让各通道更容易量化；Bias Correction 则尝试修正量化噪声引起的输出均值偏移。

它们更适合称为量化前处理或 PTQ 辅助优化，而不是独立的数值格式。能否应用还取决于模型结构，例如包含 BatchNorm 的 CNN 与纯 Transformer 的适用方式并不完全相同。

## 十、怎样选择量化方法

### 10.1 先看部署约束

选择方法前优先确认：

1. 目标硬件支持哪些位宽和量化粒度？
2. 后端是否有对应的低比特算子内核？
3. 需要降低模型容量、Activation 带宽，还是 KV Cache 容量？
4. 是否有代表性校准数据？
5. 是否允许训练或微调？
6. 可接受多少量化时间与精度损失？

算法精度高不代表一定能够在目标设备加速；如果编译器不识别其格式，最终可能发生反量化、回退 CPU/GPU，或者根本无法部署。

### 10.2 常见场景的起点

| 需求 | 常见起点 | 原因 |
|---|---|---|
| 最快建立通用 PTQ 基线 | Min-Max + 静态校准 | 简单、工具支持广 |
| AIMET/QNN 下改善 W4 精度 | QuantSim + SeqMSE + Activation Calibration | 与当前工具链和 Encoding 导出衔接 |
| GPU 上部署 Weight-Only LLM | GPTQ 或 AWQ | W4 生态和相应运行时较常见 |
| 希望使用 W8A8 整数计算 | SmoothQuant + 静态 Activation 校准 | 针对 Activation 异常值 |
| 校准分布变化非常明显 | 动态 Activation/KV 或更细粒度量化 | 能适应当前张量范围，但增加开销 |
| PTQ 精度仍不够且允许训练 | QAT | 模型可以主动适应量化误差 |

这张表只是选型起点，最终应以目标后端的支持矩阵、端侧延迟、内存、PPL 和真实任务精度为准。

### 10.3 一个简化决策树

```text
是否允许训练或微调？
├─ 是 → PTQ 先做基线；精度不足时考虑 QAT
└─ 否 → PTQ
        │
        ├─ 只压 Weight，主要跑 GPU？
        │      └─ GPTQ / AWQ
        │
        ├─ 目标是 W8A8，Activation 有异常值？
        │      └─ SmoothQuant + Calibration
        │
        └─ AIMET/QNN 固定 Encoding 流程？
               └─ QuantSim + SeqMSE + compute_encodings
```

## 十一、本项目采用了什么组合

### 11.1 基础配置

`example1/config.yaml`：

```yaml
quantization:
  quant_scheme: post_training_tf
  default_output_bw: 16
  default_param_bw: 4

seq_mse:
  num_batches: 20
  inp_symmetry: symqt
  num_candidates: 20
  loss_fn: mse

evaluation:
  compute_encodings_num_batches: 20
```

默认规格可以概括为 W4A16。

### 11.2 完整方法定位

| 维度 | 本项目选择 |
|---|---|
| 介入阶段 | PTQ |
| Encoding 时机 | 离线校准并固定，属于静态量化 |
| 默认对象和位宽 | Weight 4 bit、Activation 16 bit |
| 基础方案 | `post_training_tf` Min-Max 风格 QuantSim Encoding |
| Weight 优化 | SeqMSE，20 个 batch、20 组候选、`symqt + mse` |
| Activation/KV 路径标定 | `compute_encodings()` 对前 20 个 Batch 执行校准前向；helper 支持连续 KV 切块，但当前 VL 样本长度等于 ARN，每 Batch 只有一个块；为实际经过且已启用、允许更新的 Activation Quantizer 收集 Encoding，同时从参数张量计算或重算允许覆盖的 Parameter Encoding |
| 局部规则 | HTP 配置、MatMul/Concat 规则、混合精度例外 |
| 精度验收 | 量化后 PPL |
| 部署产物 | ONNX + `.encodings`，后续交给 QNN 编译 |

### 11.3 当前流程

```text
prepared 浮点模型
    ↓
创建默认 W4/A16 QuantSim
（构造时加载 HTP config）
    ↓
应用 MatMul、Concat 和手工混合精度规则
    ↓
SeqMSE 优化受支持层的 Weight Encoding
    ↓
compute_encodings 标定 Activation，并计算／重算可覆盖的 Parameter Encoding
    ↓
量化后 PPL 验证
    ↓
导出 ONNX + Encoding
    ↓
QNN/HTP 编译部署
```

### 11.4 当前项目不属于什么

- 不是 QAT：没有带 Fake Quant 重新训练模型参数；
- 不是运行时动态 Activation 量化：Encoding 在导出前完成标定；
- 不是 GPTQ/AWQ：代码没有执行对应的块级补偿或 Activation-aware Weight-Only 算法；
- 不是“纯普通 Min-Max”：满足条件的低比特 Weight Encoding 又经过了 SeqMSE 优化。

局部混合精度规则表达的是设计意图，规则是否真正命中当前 prepared 模块名称还需要运行时检查，详见 [07-附录C · MatMul、Concat 与混合精度](./07-附录C-量化规则配置-MatMul-Concat与混合精度.md)。

当前 `compute_encodings()` 的实际校准路径与 KV 覆盖边界，详见 [07-附录E · `compute_encodings()` 激活标定](./07-附录E-compute_encodings激活标定.md)。

## 十二、常见误解

### 12.1 “SeqMSE、W4A16 和 PTQ 是同一类概念”

不是：

```text
PTQ    → 量化发生的阶段
W4A16  → Weight/Activation 的位宽规格
SeqMSE → 选择 Weight Encoding 的优化算法
```

### 12.2 “跑了前向就是动态量化”

不是。SeqMSE 和静态 Activation Calibration 都会离线跑前向，但只要最终 Encoding 被固定并导出，仍然属于静态量化。

### 12.3 “Activation 动态产生，所以一定是动态量化”

不是。动态产生描述的是张量值，动态量化描述的是 Encoding 是否在推理时重新计算。

### 12.4 “PTQ 完全不需要数据，也不会做任何优化”

不是。基础 Weight Min-Max 可以无数据，但 SeqMSE、GPTQ、AWQ、Activation Calibration 等通常需要少量代表性样本；部分 PTQ 方法还会优化舍入、裁剪或等价变换变量。

### 12.5 “位宽越低，端侧一定越快”

不一定。还要看硬件内核、编译器支持、量化粒度、数据搬运、算子回退和反量化开销。最终必须在目标设备实测。

### 12.6 “局部层 MSE 最小，模型 PPL 一定最好”

不一定。局部重构误差是近似目标，不能完全替代端到端指标，所以 SeqMSE 后还需要做 PPL 或真实任务评估。

### 12.7 “QAT 就是动态量化”

不是。QAT 描述的是模型在训练或微调时如何适应量化误差；模型部署后通常仍使用固定 Encoding。静态或动态描述的是推理时 Encoding 是否重新计算，两者不是同一个维度。

## 十三、面试速答

### Q：量化方法应该怎样分类？

> 不应只列算法名。可以分别从量化对象、PTQ/QAT、静态/动态、数值格式和位宽、量化粒度、范围标定与误差控制策略六个维度描述。一套真实方案是这些维度的组合。

### Q：SeqMSE 和普通量化有什么区别？

> 普通 Weight Min-Max 根据权重范围直接确定 Encoding；SeqMSE 使用代表性数据逐层尝试多组候选 Encoding，比较浮点权重和候选量化权重造成的层输出误差，并冻结 MSE 最小的一组。

### Q：SeqMSE 为什么仍需要 `compute_encodings()`？

> SeqMSE 只优化受支持层的 Weight Encoding；`compute_encodings()` 还需要标定校准前向实际执行到且已启用、允许更新的 Activation Quantizer，并直接从参数张量计算或重算其他允许覆盖的 Parameter Encoding。SeqMSE 冻结的结果保持不变。

### Q：当前项目属于哪种量化？

> 当前项目属于静态 PTQ：默认 W4A16，以 `post_training_tf` 创建 QuantSim，使用 SeqMSE 优化低比特 Weight Encoding，再通过 `compute_encodings()` 标定 Activation 并处理允许覆盖的 Parameter Encoding，最后测量 PPL 并导出给 QNN/HTP。

### Q：GPTQ、AWQ、SmoothQuant 各自解决什么问题？

> GPTQ 逐块量化并利用近似二阶信息补偿 Weight 误差；AWQ 根据 Activation 识别并保护重要 Weight 通道；SmoothQuant 通过等价缩放把 Activation 异常值带来的量化难度迁移到 Weight。
