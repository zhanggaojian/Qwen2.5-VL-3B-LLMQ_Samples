## 一、先记住这条主线（项目在干什么）

**把官方 Qwen2.5-VL-3B 模型，改造 + 量化成能在高通端侧(HTP/NPU)跑的格式。** 主线脚本 `example1/llm_quant.py`：

```
读 config
  → 模型适配(Monkey Patch，改 5 处零件)     ★灵魂之一
  → 加载模型 / tokenizer
  → 浮点 PPL 评估(基准)
  → 通用定长前向处理(FPM)
  → prepare(导出中间结构)
  → 量化(QuantSim / SeqMSE / compute_encodings)  ★灵魂之二
  → 量化后 PPL(对比精度掉多少)
  → 导出 Test Vector + ONNX + Encoding          ★当前阶段
```

> **贯穿全程的一句话主线索**：**端侧要「定长 + 静态图 + 硬件友好算子」**，所以（a）把 Linear 换成 Conv、（b）把"会变长的东西（掩码、KV 历史）"挪到模型外部。**5 处适配全是这句话的落地。** 抓住它，知识点就不散了。

### L3 · 深度追问（能讲"为什么"就是加分项）

- **掩码为什么用 -50 而不是 `finfo.min`**：极端负值量化易溢出/NaN，-50 已足够 softmax 后≈0，量化友好。
- **KV 为什么量化到 8bit**：减小 KV-cache 的数据 I/O 开销。
- **prefill/decode 为什么导成两张定长图、怎么共享权重**：输入长度不同、图定长；两张图共享同一套权重。
- **`transposed_key_cache` 为什么**：K 转置存，算 `Q@K` 省一次运行时转置、布局对 HTP 更友好。
- **SeqMSE 干嘛的**：逐层搜索更合适的权重量化范围，降低量化误差（07 将逐步展开）。
- **`return_new_key_value_only` 的分工**：返回给注意力的是完整历史，存进缓存的只有新 K/V → 模型内部定长。
- **PPL 为什么用交叉熵、有无替代**：PPL 定义即 exp(交叉熵)，信息论最自然、和训练一致；替代=同源变体(NLL/BPC) 或量化专用的 KL/MSE/SQNR（SeqMSE 用 MSE 标定、PPL 顶层验收）。详见 [04-PPL 2.5](./04-PPL困惑度评估.md)。

## 五、一段能背出来的项目自述（电梯陈述）

> 面试"介绍一下这个项目"时，先讲这段 30 秒版，再按追问展开：

"这个项目把 **Qwen2.5-VL-3B** 大模型改造并量化，部署到**高通端侧 NPU(HTP)**。核心是两块：**模型适配**和**量化**。适配上，为了满足端侧'定长 + 静态计算图 + 硬件友好算子'的要求，用 Monkey Patch 在不改官方源码的前提下换了 5 处零件——把 Attention/MLP/lm_head 的 **Linear 转成 1×1 Conv**、把**因果掩码改成外部输入**、把 **KV Cache 改写成定长版**（只吐新 K/V、历史交外部管）。量化上用高通 **AIMET/QNN** 工具链，权重压到 **4bit**、激活 **16bit**，配合 **SeqMSE** 标定，并用 **PPL** 在量化前后对比精度损失，最后导出 **ONNX** 交端侧引擎运行。"

## 六、防跑偏提醒（这次凌乱的教训）
